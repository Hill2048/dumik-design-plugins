# DUMIK 参考文件与任务规则包改造

## 目标

解决 DUMIK 在实际对话中跳过、漏读或错读 skill 参考文件的问题，同时保留参考文件的模块化维护方式。

改造后，参考文件仍然是唯一真源；每次任务根据 skill、模式、模型和输出类型编译一份当前任务专用的 `reference-pack`。导演和 Runner 先读任务包，再开始工作。

## 当前问题

旧方式主要有三种风险：

1. `SKILL.md` 只给出链接，模型可能把链接当目录，不读取正文。
2. 条件参考文件写成“按需读取”，但没有明确当前任务是否命中条件。
3. 上一轮已读内容、上下文摘要或旧缓存被误认为当前版本参考，导致旧规则和新规则混用。

## 新架构

```text
当前插件安装目录
  ↓
SKILL.md + reference map
  ↓
compile_reference_pack.ps1
  ↓
任务级 reference-pack.md
  ↓
导演 / 策划 / Runner 读取同一份任务规则
  ↓
Prompt + execution_spec + QC
```

### 参考文件

`skills/*/references/` 和插件 `assets/` 继续保存完整规则、API 规范、模板和平台限制。它们不复制到其他 skill，也不因一次任务改写。

### Reference map

`compile_reference_pack.ps1` 按 skill、模式、模型和输出类型选择参考文件。除没有条件分支的安装检查外，所有 skill 都必须显式传入模式；不能用默认模式生成不完整的规则包。每次生成包都会登记当前 skill `references/` 目录下的全部文件，再追加跨 skill 的命中文件，并记录：

- 当前插件根目录
- skill、模式和模型
- 实际读取的文件路径
- 文件大小和 SHA-256
- 未命中文件的短摘要
- 命中文件继续引用的本地文件
- 生成时间
- 缺失文件和失败原因

缺文件时脚本失败，不生成看似完整的规则包。

### 任务级规则包

规则包包含三部分：

1. `Task-selected references`：本次模式、模型和平台命中的文件。
2. `Full active-skill reference inventory`：当前 skill 全部参考文件的路径、大小、哈希和摘要；未命中的文件只在这里登记。
3. `source content`：命中文件的完整正文。

当前 skill 的历史 `legacy/` 文件如果命中也会完整收录，但会标明为背景资料，不能覆盖当前 `SKILL.md`、统一路由和当前模式规则。需要审计、离线归档或迁移全部资料时，才使用 `-FullReferenceArchive`，把登记清单中的所有文件正文写入归档包。

规则包只给 Agent 使用，不直接发给图片或视频模型。最终 Prompt 必须把模型需要的有效规则展开，不能写“遵循参考文件”。

## 各 skill 的读取策略

| skill | 必读 | 条件读取 |

| `d-init` | 路由、项目环境协议、入口模板 | 当前项目 `AGENTS.md`、`design.md` |
| `d-image-director` | 路由、任务状态、图片引用、交付检查 | `edit / brief / direction / hd / repair` 对应规范和模板 |
| `d-image-runner` | 路由、任务状态、图片引用、图片执行规范 | Image2.5、Banana2、RunningHub 等模型/后处理规范 |
| `d-video-director` | 路由、任务状态、提示词编译、导演设计 | 故事板、图生视频、深度视频、摄影机、报告规范 |
| `d-video-runner` | 路由、任务状态、视频执行规范 | Veo、Seedance、平台限制和素材类型规范 |
| `d-visual-plan` | 路由、图片或视频策划规范 | Seedance 策略、项目设定 |
| `d-project-pipeline` | 路由、任务状态、批量流水线规范 | 当前任务命中的导演和 Runner 包 |

## 新的执行顺序

### 文字任务

```text
路由
→ 判断 skill / mode / model
→ 编译 reference-pack
→ 读取 reference-pack
→ 建立任务合同
→ 输出 Prompt / 策略 / 分镜
```

### 真实执行

```text
读取导演结果
→ 编译 Runner reference-pack
→ 核对素材、模型、比例、时长和 API
→ 生成 execution_spec
→ 发包
→ 按规则包中的 QC 复核
```

### 规则包失败

出现以下情况时必须停止依赖该规范的工作：

- 当前文件不存在
- 当前安装目录无法确认
- 参考文件读取失败
- 任务模式无法判断
- 模型或平台规范缺失
- 规则包生成后文件被改动

可以继续做不依赖该文件的路由判断，但不能套旧规则、凭经验补齐或直接执行。

## Prompt 与规则的边界

规则包负责 Agent 的判断和编译；最终 Prompt 只保留生成模型需要的内容：

- 素材角色
- 主体和动作
- 构图与镜头
- 材质、光线和色彩
- 连续性和关键锁定项
- 比例等模型真正需要的画面约束

模型不需要看到 API Key、接口地址、脚本路径、内部路由或项目文件名。

## 优势

- 当前任务的参考来源可审计。
- 规则更新后不需要复制到每个 skill。
- 导演和 Runner 可以分别使用不同的任务包。
- 模型、平台、比例和后处理规范不容易被漏掉。
- 适合恢复、压缩和跨对话继续，因为包里有实际文件和哈希。
- 最终 Prompt 仍然可以保持短，不把内部规则发给生成模型。

## 代价与控制

- 多一步编译：用脚本自动完成，不让 Agent 手工拼接。
- 规则包可能过长：默认只编译命中文件正文，未命中文件保留摘要和哈希；命中文件引用的本地规则会继续跟进；完整归档才加载所有正文。
- 参考文件可能冲突：以当前 skill 的统一主线、任务合同和模型规范为优先级。
- 包可能过期：执行前复核文件哈希；变更后重新编译。
- 脚本不是语义判断器：模式选择仍由 skill 负责，条件选择必须在 `SKILL.md` 中写清楚。

## 完成标准

本改造完成后，每个有参考文件的 skill 都必须做到：

1. 明确必读和条件读取文件。
2. 当前 skill 的全部 `references/` 文件都进入任务包登记，不再因模式判断漏掉同目录文件；当前命中文件进入正文。
3. 能用统一脚本生成任务级规则包。
4. `SKILL.md` 明确禁止未完成规则包就输出或执行。
5. 规则包包含全量来源登记、命中文件完整正文和读取回执；需要时可生成全量正文归档。
6. 所有相对引用存在，脚本可以通过基础校验。
7. 现有用户路由、模型名、API 和输出目录不被改变。

# 详情页批量出图编排器

本方法在已有批量执行授权内组织生成，不为批量任务另外扩大授权。项目 `AGENTS.md` 决定协作和确认方式，本文件只维护任务依赖与执行状态。

不需要另起前端、桥服务或端口。策略、画面准备、生成和修复只在当前任务需要时调用。

唯一的落盘是一份**轻量 run-state.json**，写在 `制作/图片/<任务名>/`，只给 Agent 自己用：会话中断后凭它断点续跑，不用从头重来。它不是对外合同，没有前端读它。

## 触发

- 用户明确说：批量出详情页、整套详情页自动跑、项目制批量抽卡。
- 已有视觉设定或能现做，且卖点清单 ≥ 1。

不触发：用户只要一句提示词、一次改图、单卖点手动探方向 —— 那走原有逐步链路。

## 前置

进入前确认：
- 用户指定的项目目录已就位，已读该项目 `AGENTS.md`；不使用项目指针文件。
- 图片接口可用（按 `d-image-runner` 的 API 缓存规则）。
- 默认参考只来自 `design.md` 和 `设定集`。用户本轮明确给出的文件可用于本次任务；不得从素材、制作、成品或外部素材库自动找参考，也不得把流水线候选自动回垫。

## 状态文件（断点续跑用）

路径：`制作/图片/<任务名>/run-state.json`。每推进一步、每出一张图就更新它。**进入流水线前先读它**：

- 不存在时，为当前明确任务建立记录；`stage=done` 不代表自动开始新一轮。
- `stage=await_*` 时，核对该等待项是否已由用户后续反馈解决，只保留尚未解决的等待，不重复索取已经取得的确认。
- 生成中途恢复时，先核对已有任务 ID、状态与结果；仍在运行的查询原任务，成功的不重抽，失败或状态不明的不直接重复付费提交。

字段保持精简，够 Agent 自己恢复即可：

```json
{
  "schemaVersion": 2,
  "projectName": "纯钛+乌檀木菜板 详情页",
  "updatedAt": 1733500000000,
  "stage": "batch_draw",
  "sellingPointId": "双面生熟分离",
  "message": "批量抽卡：12 张已出 7 张",
  "openGate": null,
  "stats": { "total": 12, "running": 3, "done": 7, "failed": 0 },
  "tasks": [
    {
      "id": "卖点A-方向2-cand-1",
      "title": "双面生熟分离 · 方向2 · 候选1",
      "sellingPointId": "双面生熟分离",
      "directionId": "double-side-direction-2",
      "routeId": "material_macro",
      "status": "Success",
      "promptText": "引用视觉设定的完整中文提示词……",
      "resultImage": "制作/图片/<任务名>/卖点A-方向2-1.png",
      "qaVerdict": "pass",
      "qaNotes": ""
    }
  ]
}
```

写盘用「先写 `.tmp` 再改名」，避免中断时留半截文件。`stage` 取值：`planning / pilot / await_direction / calibrating / batch_draw / await_selection / qa_repair / await_final / done`。

## 按依赖组织任务

`stage` 是运行记录，不是必须逐一经过的审批顺序。下面说明各类工作的输入与输出；实际需要哪些工作、在哪里等待，由项目 `AGENTS.md` 和任务要求决定。

### 准备与试跑

- 用现有需求和有效决定建立任务；只有缺本次确需的策略时才调用 `d-visual-plan`。
- 画面与提示词交给 `d-image-director`。试跑仅在当前任务需要时组织，不固定第一卖点或四宫格。
- 方向、数量、输入素材及允许变化以项目给定要求为准，不把探索结果自动升级为全项目设定。

### 并发与等待

- 准备好独立任务行，每行使用独立 ID、输出名、完整提示词和真实参考输入；按执行器接口组织 `count`。
- 只提交输入和依赖已经满足、且在当前授权范围内的任务。与等待项无关的已批准部分可继续，不要求全部卖点选完再推进。
- 接到执行器状态即更新 `tasks[]`、`stats` 和结果位置。需要等待时记下实际等待项；解决后清理对应 `openGate`，不直接清空所有未解决事项。

### 结果与修复

- 保留所有候选、原始结果和输入记录。展示、推荐与验收按项目规则执行，不在编排器内部设定审美淘汰规则。
- 需要修复的已选任务交给 `d-image-director`，按其技术方法切图、重绘或贴回。保留原版，执行次数与费用不超过授权。
- 修复或重做只更新受影响任务；技术经验留在任务记录，反馈是否推广由项目总控决定，不自动回写 `design.md` 或全局 prompt-pack。

### 交付

- 项目明确通过的结果进入对应成品目录，记录它的源任务与结果文件。仅接受本次结果不产生新的参考使用范围。
- 本次应交付事项完成后才记 `stage=done`；尚有未解决等待或失败项时如实保留状态。

注意：本流水线交付的是**确认图/成品图**，不含文字、参数、logo、版式叠加（那是后续确定性叠加层，不在本 skill）。

## 执行约束

- 未解决的依赖和项目要求的确认不能跳过；已解决的确认也不能机械重问。
- 不另写反馈推广或项目协作规则，不强制创建 `校准沉淀.json`。
- 提示词交 `d-image-director`，生成交 `d-image-runner`，不在编排器里另造接口参数或模型调用路径。
- run-state 只为 Agent 自己断点续跑，不对外、不接前端、不起服务；不要把它当成给别人读的合同来设计字段。

## 交接

- 策略缺失 → `d-visual-plan`
- 抽卡提示词 → `d-image-director`
- 实际生成 / 批量 → `d-image-runner`
- 细节修复 / QA → `d-image-director`
- 顶层协作与调度 → 项目 `AGENTS.md`

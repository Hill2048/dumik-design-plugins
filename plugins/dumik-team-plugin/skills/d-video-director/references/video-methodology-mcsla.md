# 视频方法论：MCSLA 与提示词构造

> 来源：Higgsfield 官方《Hell Grind》开源工程档案（95 分钟 AI 长片，15 人 / 14 天 / 50 万美元 / 115,446 次生成 / 4 万余条提示词）及其衍生方法论整理。
> 本文只保留**提示词构造与导演方法**，已剔除平台工具、CLI、模型调用参数与账号流程。
> 适用：DUMIK 视频线的提示词编译层，与 `prompt-compiler.md` 配合使用；冲突时以 DUMIK 编译器为准。

## 一、MCSLA 五层公式

每一条高质量视频提示词都由五层构成。可以把它当作摄影师的检查清单：逐层填满，模型就拿到了它需要的全部信息。

| 层 | 元素 | 作用 | 示例 |
|---|---|---|---|
| **M** | Model | 生成引擎的取向（**在 DUMIK 中只进 `execution_spec`，不写进正文**） | — |
| **C** | Camera | 具名镜头控制 | 「FPV 无人机穿过巷道」 |
| **S** | Subject | 谁 / 什么 + 外观 | 「穿沙色西装的女人，眼神锐利」 |
| **L** | Look | 风格 + 色彩 + 光照 | 「电影感、黄金时刻、变形宽银幕眩光」 |
| **A** | Action | 场景中发生了什么 | 「她缓慢转身，风掀起大衣」 |

**DUMIK 适配**：M 层在 DUMIK 里由 `execution_spec` 承担，正文只写 C/S/L/A 四层。这是与原始方法论的唯一结构性差异。

## 二、两种提示词范式

### 文生视频（T2V）

```
[主体 + 外观]。
[环境 —— 地点、时间、天气、氛围]。
[动作 —— 发生什么、如何发生]。
[镜头 —— 具名控制]。
[观感 —— 风格 + 调色]。
```

示例：

```
一名孤独的宇航员站在红色沙漠星球表面，头盔面罩反射出地平线上正在升起的双月。
稀薄大气中尘埃缓缓盘旋。她转向镜头，戴手套的手举起做一个缓慢的敬礼。
镜头：缓慢升起的摇臂镜头，揭示身后广袤的空旷。
风格：电影感，低饱和橙与深蓝，2.35:1 变形宽银幕。
```

### 图生视频（I2V）

**核心规则：绝不重新描述图中已有的内容。** 只描述应当**变化**或**运动**的部分。过度描述静态元素会让模型混乱。

```
[把输入图作为首帧]。
[描述什么会动、会变 —— 不是已经可见的东西]。
[镜头 —— 具名控制]。
[风格 / 氛围线索]。
```

示例：

```
从提供的图片作为首帧开始。
女人的头发在风中轻轻扬起。她缓慢眨眼，视线略微转向左侧，一丝浅笑浮现。
镜头：朝她面部做细微推近。
风格：电影感，温暖的午后光线，浅景深。
```

## 三、叙事结构

### 流动叙事（多数场景首选）

把场景写成连续动作，不加时间戳。这是最自然的结构。

```
一名侦探推开雨夜天台的门，大衣在风中翻卷。她走到边缘，俯视下方城市 ——
千百盏灯火在暴雨中晕开。镜头缓慢跟在她身后，然后升起，露出天际线。
电影感风格，冷蓝色调，16:9。
```

### 时间戳结构（只在需要精确多节拍时使用）

```
0-3 秒：<起始状态与第一个动作>。
3-7 秒：<承接，第二个动作>。
7-10 秒：<收束与结果>。
```

**注意**：时间戳只表示事件预算，不是帧级剪辑点。不要声称能精确到 0.5 秒。

## 四、一条铁律：每个片段一个主动作

- 每镜**一个主动作**，最多 1–2 个次要动作。
- 多动作会互相抢夺模型的注意力，导致每个动作都不完整。
- 需要多动作时：拆成多镜，或用「快速动作技巧」——先以慢动作生成，后期加速。

## 五、情绪必须可观察

**永远不要在提示词里留下笼统情绪词**（sad / angry / 难过 / 愤怒）。必须拆解成可见的身体证据：

```
笼统：她很难过。
可观察：她的下颌绷紧，吸气时肩膀轻微抬起，视线落在桌面不动，
        下眼睑先湿润，然后才眨眼。
```

拆解顺序：肌肉动作 → 呼吸 → 眼睛 → 皮肤 → 姿态。

## 六、角色一致性：身份块与动作块必须分离

这是《Hell Grind》最核心的工程发现。

**规则**：每个提示词拆成两个互不混合的块。

```
【身份块】只写：脸型、五官、发型、服装、配饰、体型比例、固定标识。
【动作块】只写：这一镜的动作、走位、表情变化、镜头运动。
```

**绝不把身份描述混进动作句，也绝不把动作写进身份块。**

配套规则：

- **角色表不负责好看，只负责稳定。** 参考图要故意做得「无聊」：中性背景、平光、真实皮肤、普通姿势，像证件照。光影太花哨，模型会连光影一起学，下一镜换环境就崩。
- **一张图只干一件事。** 全身图里的脸太小，模型采样五官容易崩；不如明确告诉它：这张图只看身材比例与服装，脸去看另一张高清近景。
- **一个角色不是一张图，而是一个资产家族。** 正常状态、湿透、战损、便装、童年……每种状态各做一张标准参考。

## 七、场景锚定：给模型一张片场地图

视频模型单次生成时长有限，长片靠拼接。拼接不崩的前提是**空间可复现**。

每个场景建立一张 **GEO 空间布局块**，在每镜提示词里重复：

```
【场景锚定 · <场景名>】
主光逻辑：<唯一光源及其方向>
空间骨架：<主体位置、参照物、前后层次>
不可漂移：<轮廓、比例、关键结构、固定道具>
```

在每镜开头重复本镜需要的锚点，不要指望模型记得上一张。

## 八、禁令字典

《Hell Grind》的提示词里约 25% 带 NEGATIVE 段落。这些禁令本质上是一份**倒着写的模型翻车清单**。

DUMIK 用法：把禁令写成**正向约束**（多数模型没有负面提示词语法）。

```
不要写：不要变形、不要融化、不要出现第二个人。
改写成：木料始终保持固体形态与固定轮廓；画面内只有一个人物。
```

## 九、迭代纪律

### 单变量迭代

每次重生成**只改一个变量**。改两个以上就无法判断哪个改动起作用了。

### 6 轮诊断顺序

画面不对时，按这个顺序排查，**多数问题落在第 1–2 轮**：

1. **主体** —— 身份、数量、轮廓对不对
2. **动作** —— 主动作是否发生、是否完整
3. **镜头** —— 机位、景别、运动是否符合预期
4. **风格** —— 光色、质感、调色
5. **声音** —— 音效、环境声、对白
6. **输出** —— 画幅、时长、分辨率

### 系统性 vs 随机性

- 同一个失败**重复出现** → 系统性问题，改提示词。
- 同一个失败**偶发** → 随机性问题，多跑几条选最好。

## 十、反套话词表

**必须删除**：beautiful、stunning、epic、amazing、cinematic masterpiece、高级、震撼、绝美、电影级。

**替换为**：具体视觉事实与物理规律。

```
不写：极其逼真的木质纹理。
改写：板面年轮连续，边缘有 2mm 圆润倒角，侧光下木纹高光柔和滚降。
```

## 十一、镜头语言硬规则

- **同一镜内不得同时 Dolly In + Dolly Out。**
- **每个切点必须同时改变景别与机位性格**（双对比切镜规则）。
- **引擎跟踪上限**：跨切镜可稳定跟踪的角色不超过 3 个。
- **出画即消失，画外即不存在。** 不要让镜头外的元素在下一镜凭空出现。
- **避开反射面**：镜面反射是 AI 视频最常见的崩坏点。
- **场景默认「进行中」**：除非明确写「开始时…」「结束时…」，否则场景一开始就在动作中。

## 十二、角色年龄的中性写法

不要用 boy / girl / child / kid / young / teen / little（男孩、女孩、孩子、年轻、少年、小）。

改用**角色身份 + 服装 + 动作**来描述。年龄词会让模型强行拉低角色成熟度，破坏一致性。

## 十三、对白容量

15 秒内可容纳的口语约 **25–30 个词**。超出就把次要台词转成行为与反应，只保留推动力量关系的那一句。

## 十四、与 DUMIK 编译器的衔接

本文件是**方法论层**，不替代 DUMIK 的编译合同。执行顺序：

```
d-visual-plan（商业目标与卖点顺序）
  → 本文件（MCSLA、I2V 规则、身份/动作分离、场景锚定、禁令、迭代）
  → prompt-compiler.md（故事合同、素材职责、主任务路由、参数分离）
  → directing-design.md（镜头命题、观众位置、视线、物理光色）
  → seedance-camera-codec.md（复合轨迹与速度曲线）
  → d-video-runner（执行）
```

**冲突处理**：DUMIK 编译器与导演调度优先于本文件；本文件只补充 DUMIK 尚未覆盖的规则（身份/动作分离、单变量迭代、6 轮诊断、反套话、双对比切镜、年龄中性、对白容量）。

# DUMIK 统一视频提示词编译器

本文件是 `d-video-director` 所有视频提示词任务的核心逻辑。它以官方
`sd25-pe` 的故事合同、素材映射和任务路由为方法来源，叠加 DUMIK 的产品身份、
商业证据、内容设计和物理运镜规则；Seedance 2.5 只是末端模型适配器之一。

## 核心地位

- 任何写、改、补全或返修视频 Prompt 的任务都先使用本文件，不再把它当作可选的 2.5 分支。
- `d-visual-plan` 提供商业目标、卖点顺序和证据链；本核心把它编译为可拍事件与干净 Prompt；`d-video-runner` 负责模型能力、执行参数、额度提示、确认片和批量闸门。
- 内容设计与导演调度是所有提示词共同必经的编译阶段，不是 `cinematic` 模式。`templates.md`、产品身份、故事板、深度视频、烹饪运动和相机 codec 只补充特定素材或交付结构。发生冲突时，本核心的意图保真、素材映射、主任务路由、参数分离和输出合同优先。
- 本核心只读素材，只输出文本，不调用生成接口、不修改素材，也不执行外部 `sd25-pe` 的自动升级命令。

## 编译产物

核心内部形成四个对象，不要混在同一段 Prompt 中：

1. `story_contract`：人物/产品/道具/场景、数量、关系、因果、起止状态和用户明确约束。
2. `reference_manifest`：每份素材的编号、实体槽位、采用属性、排除属性和未采用集合。
3. `final_instruction`：单条可提交 Prompt，只写当前任务内容与素材职责。
4. `execution_spec`：目标模型、任务类型、画幅、时长、分辨率、帧率、声音开关和本地文件路径。

用户只要提示词时默认只交付 `final_instruction`。交给 `d-video-runner` 时同时提供 `reference_manifest` 与 `execution_spec`，但不得把执行参数重新拼回 Prompt。

## 1. 编译顺序

按下面顺序整理，不要把多个角色、多个素材或多个主任务压成一句模糊描述：

```text
目标与证据 → 故事合同 → 必需实体 → 逐份素材职责 → 主体映射
→ 内容设计与导演调度 → 主任务路由 → 阶段/时间线 → 首尾或关键帧
→ 镜头、声音和可见结果 → 最终自检
```

### 故事合同

先锁定用户真正要求的事实：人物和数量、商品 SKU、关键道具及归属、场景、空间关系、动作因果、台词/声音、编辑对象、延长方向和结束状态。素材只能补充直接可见或可听见的属性，不能把服装、姿态或文件名推成年龄、职业、关系或剧情事实。

把每个明确人物、群体、产品、道具和场景列成内部槽位。输出前逐项核对每个槽位都进入 Prompt；不能把两个命名角色合成一个主体，也不能用一张单人图同时定义两个同时出场的人物。

输入包含对白、旁白或音频职责时，在 `story_contract` 内建立对白账本：逐阶段记录说话人、原始台词、语言、画内/画外位置和音频职责。用户只给短句时不得补成完整新台词；只给说话意图而没有原文时，用口型、停顿、姿态和对方反应表达，不编造对白。

保留编号语义。`镜头45`、`Shot 45`、素材编号、步骤编号默认都是编号；只有用户明确写出 `45 度` 或等价表达时，才把数字解释成机位角度。

信息优先级固定为：

```text
用户明确指定 > Prompt 中的描述 > 素材可观察内容 > 文件名/元数据 > 上传顺序
```

无法影响核心结果的歧义可采用最保守假设并在 Prompt 外说明；会改变身份、数量、道具归属、朝向、编辑对象、唯一母版、关键帧职责或延长方向的歧义只合并询问一次。

## 2. 参数与任务路由

### 参数分离

画幅、总时长、分辨率、帧率、模型和声音开关属于 `execution_spec`，不写进任何目标模型的 `final_instruction`。用户写出的事件时间段属于创作内容，只有在它确实描述事件节拍时才保留；不能为了配合页面时长新造 `0-8 秒`、`8-18 秒` 这类数字段。

产品、镜头和声音仍要写具体；不要用“按 9:16 输出”“生成 5 秒视频”替代画面内容。事件密度可以参考目标时长，但参数本身只放任务行。

### 只选一个主任务

多素材、长视频、关键帧、宫格、白模、情绪和声音是可叠加模块，不是新的主任务。主任务只能是：

1. **生成**：从文字和参考素材创建新视频。
2. **编辑**：以一条原视频为唯一母版，只改指定对象、区域或声音。
3. **延长**：只在原视频首帧之前或尾帧之后新增连续片段，不改写原片段。

编辑和延长同时出现时拆成两个顺序 Prompt：先编辑得到新母版，再延长；不要把两种意图混成一条。

### 规格兼容性闸门

只有目标画幅与原视频一致（或均未指定）、基本时长一致，并且用户明确修改原视频对象/区域/声音时，才进入编辑。目标画幅不同或时长变化明显时，按生成处理；参考视频只承担内容、动作、时序、镜头和声音参考，不承诺逐帧一致。此时在 `【生成目标】` 后追加一次：`请注意这不是视频编辑。`

## 3. 目标模型适配器

核心编译完成后只运行一个适配器。适配器可以删减目标模型不支持的职责或返回能力缺口，不能改写故事合同、素材映射和结局。

### Seedance 2.5

- 保留生成、视频编辑、声音编辑、向前/向后延长、首尾帧、多关键帧、多素材、宫格和白模结构。
- 单次目标视频可按最长 30 秒规划；图片最多 30 张、视频最多 10 段且总长不超过 30 秒、音频最多 10 段且总长不超过 30 秒，三类合计最多 50 份。提交前仍以实际页面/API 为准。
- 画幅、总时长、分辨率、帧率和声音开关只进入 `execution_spec`。

### Dreamina / Seedance 2.0

- 沿用同一故事合同、素材映射、事件状态、产品锁定、相机和声音逻辑。
- `ratio`、`duration`、`video_resolution`、`model_version` 只进入 Runner 任务行；`final_instruction` 不重复这些参数。
- 媒体数量、时长、首尾帧、编辑和延长能力以实时 `dreamina <subcommand> -h` 为准。不支持的 2.5 专用能力必须停止或拆成当前 CLI 可执行的步骤，不得伪装成已支持。

### Veo

- 保留人物/产品身份、单镜事件、起止状态、摄影机和可见结果；只激活 Veo 实际支持的图像参考。
- 当前 DUMIK Runner 不给 Veo 传参考视频或参考音频，也不把编辑/延长任务伪装成生成任务。比例、时长、分辨率和音频开关由 Veo 任务行管理。
- 目标要求超出当前 Veo 路径时返回能力缺口，不能改写用户故事来迁就接口。

### 未指定模型

输出模型中立的 `final_instruction` 和独立 `execution_spec` 草案，不擅自写模型名或静默选择另一模型。真实提交前由 Runner 根据用户选择和当前 CLI 能力定稿。

## 4. 素材职责与映射

每份激活素材只承担明确职责，并逐份写入 Prompt：

- 图片：人物外貌/服装、产品结构/材质、道具、场景、光线或关键帧。
- 视频：动作、运镜、节奏、时间线，或编辑任务的唯一母版、延长源视频。
- 音频：指定说话人的音色/台词、环境声、动作音效或音乐。

不同实体逐条绑定，例如“人物 A 对应 @图片1”“道具 B 对应 @图片2”，不要写“人物 A 和 B 参考 @图片1、@图片2”。参考视频只继承被点名的维度，不默认继承其中的人物身份、服装和完整场景。

用户原文已有 `@图片N`、`@视频N` 或 `@音频N` 时必须保留原编号和职责。素材未附带、损坏或当前环境不可读取时，只使用文字能确认的事实：不声称已经查看，不按文件名猜内容，不删除或改号用户已有引用，也不凭空增加新引用。

多素材可读取时分两遍理解：第一遍轻量盘点全部素材，识别人物、产品、道具、场景、动作、运镜、节奏和声音候选；第二遍只深读与故事槽位匹配、互相冲突、作为关键帧或当前阶段会调用的素材。视频至少核对主体、主要动作、镜头变化、开头与结尾状态；音频至少核对声音类型、语言、台词或环境声职责。

用户已明确素材职责时，不用相似但未点名的素材覆盖它。能够取得完整素材清单时，把实际可用但未分配的素材逐个放入 Prompt：

```text
【未采用素材】
@图片5、@视频2未参与本任务，不用于人物、场景、道具、动作、镜头或声音。
```

素材输入范围由目标模型适配器检查。超过硬范围时先保留用户明确指定的素材、核心实体、唯一编辑母版、延长源视频和边界帧；其余素材进入未采用集合，并在 Prompt 外追加一条 `素材提示：`。推荐范围不是阻塞条件。

## 5. 事件、阶段和产品证明

产品或功能不要写成“展示智能、可靠、安装运行全过程”，改成可观察的状态链：

```text
开始状态 → 一个具体操作/事件 → 可见结果
```

每个阶段只保留一个主要状态变化，并写清结束状态；交接、抓取、放置要写唯一物体的归属变化。长视频优先使用不带数字的阶段组织，阶段数量由事件数量决定：

事件密度按 `execution_spec` 中的目标时长规划；模型允许的最长时长由适配器决定。不能从 Prompt 能容纳多个阶段推导为当前执行器已经支持。

```text
【阶段一】
开始时：<初始状态>。
主要事件：<一个具体动作>。
结束时：<可观察结果>。

【阶段二】
承接上一阶段：<必须保持的状态>。
主要事件：<下一个具体动作>。
结束时：<可观察结果>。
```

页面给出的更长目标时长只用于分配动作过程、视线转移、停顿和过渡的节奏；不能新增人物、主线事件、重复动作或新的故事结果。

存在因果揭示时先让观众看清触发原因，再呈现主体反应；原因与反应距离较远时，用一次明确视线或镜头转移建立关系，不能只留下脱离原因的反应特写。

## 6. 首帧、尾帧和关键帧

首尾关键帧必须逐张、逐句声明，不能合并成“参考 @图片1-2”：

```text
@图片1作为首帧。
该首帧定义开始时的构图、主体位置、姿态、道具状态、场景和镜头方向。
@图片2作为尾帧。
该尾帧定义结束时的构图、主体位置、姿态、道具状态、场景和镜头方向。
```

随后写一条连续动作，让画面从首帧自然到达尾帧，并保持身份、数量、道具归属、空间方向和摄影轴线。中间关键帧是语义锚点，不是要求静止或逐像素复刻；多关键帧先声明顺序，再逐张定义阶段状态。

首帧比例会锁定输出比例，首尾应使用相同画幅；这些是提交前预检，不写回 Prompt。首帧、尾帧职责高于普通主体/场景参考，但不能因此改变用户已指定的素材映射。

## 7. 宫格分镜与白模

宫格分镜只定义读取顺序、镜头结构和大致构图，不要求逐格细节硬复刻。必须写明从左到右、从上到下的阅读顺序，并明确不采用边框、网格线、SHOT 编号、注释、UI、线稿画风和占位人物；成片不生成这些板面元素。

白模先判断职责：

- 粗粒度白模：逐个把几何体映射到最终人物/道具，只继承动作路径、站位、机位、运镜、切镜、空间和节奏，不采用白模外观。
- 细粒度白模：继承主体/道具结构、动作、空间和镜头，再用明确素材重渲染人物、材质、颜色和场景。

白模视频是生成参考，不会因为“是视频”就自动成为编辑母版；轨迹线、坐标轴、控制器、相机锥体和文字标记都不进入成片。

## 8. 编辑与延长

### 视频编辑

编辑 Prompt 必须闭合四件事：唯一原视频母版、明确修改对象/区域、目标数量、其余内容如何保持，以及目标对象如何继承原时间线。画面编辑先盘点可见主体类别，未点名对象默认保持原样；无法完整查看原片时使用兜底句：

```text
除以上明确修改对象外，@视频1中其他可见人物、道具和背景元素保持原样，不参与替换或删除。
```

动态跨类别替换优先写“运动槽位覆盖”：删除原主体，让目标主体继承相同出现时机、路径、速度和遮挡位置，并声明原主体不再出现。声音编辑仍以原视频为唯一母版，只改指定声音；画面、口型时点、镜头、剪辑节奏和其他声音保持不变。

### 视频延长

“延长”但没有向前/向后方向时先询问一次。向后延长的第一画面承接尾帧，向前延长的最后画面衔接首帧；两者都要保持主体姿态与朝向、道具状态、背景空间、机位构图、光线、声音状态和运动趋势。同一主体始终是一个连续实例，不复制、不分裂，部件数量和拓扑关系与边界帧一致。

延长只创作边界之外的新片段，不同时编辑原视频；新增素材不能覆盖边界帧对画面和声音的控制。

## 9. 情绪、摄影和声音

每个画面都先做设计判断：这一镜承担什么信息或情绪任务，主体如何调度，观众站在哪里，视线从哪里进入并落到什么证据，光色来自什么现实光源，画面需要多少信息，以及它与前后镜如何连续。详细方法读取 `directing-design.md`。

这项判断不等于每镜都要复杂运镜、强情绪或广告化布景。静镜、留白、遮挡、普通环境光和简单动作都可以是正确选择；只有当运动能揭示信息、形成证据、改变关系或承接因果时才使用。产品视频保护产品真实性与卖点证据，内容或剧情视频保护人物关系、事件因果和观看节奏。

情绪词必须落到可见证据：`触发事件 → 眼神/眉头/嘴角/呼吸/视线/手部/姿态变化 → 镜头、光线或声音变化`。只选少量最清楚的表现，不凭空增加新事件。

摄影术语必须补齐作用主体、起始位置、运动方向、到达状态和速度曲线。DUMIK 的 `seedance-camera-codec.md` 继续负责实体机位、复合轨迹、视差和非线性速度；核心编译器负责把它们放进连贯事件中，不把复合轨迹粗化成“镜头拉近”。

声音按职责分开：音乐用 `()`，音效用 `<>`，台词用 `{}`，字幕用 `【】`。每个说话阶段逐一绑定说话人、台词、语言和画内/画外位置，其他角色自然闭口聆听。用户没有指定语言或口音时不得擅自补普通话、方言或地区口音；无对白时明确人物闭口、无旁白和不显示字幕。

## 10. 最终 Prompt 合同

默认只交付一条干净 `final_instruction`。可以保留 `【生成目标】`、`【参考素材职责】`、`【主体与关系】`、`【事件脚本】`、`【保持一致】` 等 Prompt 内标签，但不输出分析过程、模型名、执行参数、接口、内部评测或修改理由。用户明确要求故事板、逐镜表或 Runner 任务行时，才把这些作为 Prompt 外的独立交付物。

不要自动加入“画质包、稳定包、不要分身、不要水印”等通用负面词。只有用户要求，或素材中确实存在且本次必须清除的文字/水印/对象，才写对应范围约束。产品任务仍必须锁定 SKU、轮廓、比例、材质、颜色、品牌区和关键部件。

输出前检查：主任务唯一；每个必需实体覆盖；素材一一负责且未采用集合不漏；事件有起始和结束状态；关键帧顺序正确；编辑/延长边界完整；声音不串人；镜头有明确目标和连续速度；Prompt 没有把执行参数写进去。

### 提示词返修

项目总控提供本次有效的任务内容及允许变化的部分，反馈适用范围不在本编译器另行定义。将这些输入整理为 `story_contract`、`reference_manifest` 和 `execution_spec`，把变化落到相关字段，检查动作因果、镜头轴线、声音关系和素材映射是否仍然一致。最终形成独立完整的 `final_instruction`，不把历史补丁或无关的通用负面词累积给模型；面向用户的展示形式遵循项目要求。

## 11. 可直接套用的骨架

### 普通生成 / 多模态生成

```text
【生成目标】
生成<核心事件>，核心主体是<主体与数量>，故事结果是<结束状态>。

【参考素材职责】
@图片1用于<主体/产品>的<明确属性>。
@视频1用于<动作/运镜/节奏>，不采用其中的<不相关身份或场景>。
@音频1用于<说话人/环境声/音效/音乐>。

【主体与关系】
<主体A>对应@图片1，始终保持<身份、数量、结构、道具归属和空间关系>。

【事件脚本】
开始时：<人物、产品、道具和场景初始状态>。
主要事件：<一个连续动作或事件>。
结束时：<可直接看到的结果和主体/道具最终位置>。

【保持一致】
保持<产品 SKU、轮廓、比例、材质、品牌区、关键部件、人物服装、空间方向和声音关系>稳定。
```

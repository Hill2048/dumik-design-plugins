# 表演导演与失败诊断

> 来源：Higgsfield《Hell Grind》生产实践中的 acting director 与 failure-modes 方法论。
> 本文只保留**表演控制与故障诊断**，已剔除平台工具与模型参数。
> 用途：当画面「对但不好看」「角色像在摆姿势」「动作没做完」时，用本文诊断和修复。

## 第一部分：表演方法

### 什么算好表演

好表演是**压力下的行为**，不是表情展示。观众要看的是：一个人想要什么、被什么挡住、试了什么办法、结果如何。

### 每场戏的五根柱子

| 柱子 | 问题 | 写进提示词的形态 |
|---|---|---|
| **目标** | 这个角色此刻想要什么？ | 一个具体、可观察的目的 |
| **障碍** | 什么挡着他？ | 人、物、空间、时间或自身 |
| **策略** | 他用什么办法？ | 一个具体的动作或话术 |
| **节拍** | 策略在何时改变？ | 每次策略转换是一个节拍 |
| **潜台词** | 他没说出口的是什么？ | 用身体与视线泄露，不写台词 |

**提示词里不出现这些术语**，但每一镜都应该能回答这五个问题。

### 从结局命名事件

不要写「他们在吵架」。要写「这场戏以谁让步结束」，然后倒推整场的行为。

```
差：两个人在厨房争吵。
好：以丈夫先移开视线结束 —— 他三次想插话都被打断，
    最后一次他放弃了，转头去看水槽。
```

### 身体动作是通道

情绪通过身体走，不通过形容词走：

- 下巴绷紧 / 放松
- 呼吸变浅 / 变深
- 肩膀前压 / 后展
- 手指收紧 / 松开
- 重心前移 / 后撤
- 视线停留 / 游移

### 倾听与反应

**反应比台词重要。** 听的人怎么反应，决定了这场戏是否成立。

写反应时给三件事：**视线落点、呼吸节奏、一个微动作**。

```
好：她听的时候视线落在对方领口，呼吸停了一拍，右手拇指摩挲杯沿两次。
```

### 眼睛必须有生命

**这是 AI 表演最常失败的地方。** 空洞的凝视立刻暴露是生成的。

写眼睛时要给：

- 焦点在哪（具体对象，不是「看向远方」）
- 眨眼节奏
- 瞳孔/眼睑的微变化
- 视线移动的路径与速度

```
差：她望着窗外，若有所思。
好：她的视线从窗框左上角缓慢下移到街道，眨了一次眼，
    下眼睑在眨眼后停留闭合了半秒才完全睁开。
```

### 状态，不是过渡

模型很难演「正在变化」。**写状态，让剪辑承担变化。**

```
差：她从平静逐渐变得愤怒。
好：切 1 她平静，手放在桌上；切 2 她的手已经握成拳，指节发白。
```

### 声音是固定身份

**音色一旦确定就不要改。** 声音属于角色身份块，不属于动作块。同一角色跨镜的音色、语速、口音必须一致。

### 群戏与空间

多人同框时：

- 明确每个人的站位（左/右、前/后、朝向）
- 明确谁在说话、谁在听
- 听的人要有反应，但不要抢戏
- **跨切镜可跟踪角色 ≤ 3 个**，超过就要拆镜

## 第二部分：失败诊断

### 诊断顺序（6 轮）

画面不对时按此顺序排查，**多数问题落在第 1—2 轮**：

1. **主体** —— 身份、数量、轮廓对不对
2. **动作** —— 主动作是否发生、是否完整
3. **镜头** —— 机位、景别、运动是否符合预期
4. **风格** —— 光色、质感、调色
5. **声音** —— 音效、环境声、对白
6. **输出** —— 画幅、时长、分辨率

### 常见失败模式与对策

| 症状 | 机制 | 对策 |
|---|---|---|
| **动作被截断**（切点在结果之前） | 时长不够，或动作描述没有终点 | 明确写「结束时 <可见结果>」；缩短前置动作；加时长 |
| **哑剧式操作**（手在动，物体不动） | 模型把操作演成手势 | 写清物体与手的接触关系、物体被移动后的位置变化 |
| **群体镜头出现多余肢体** | 多人同框时肢体归属不清 | 减少同框人数；明确每个人站位与朝向 |
| **复合运镜过载** | 一镜塞了多个运动 | 一镜一条主轨迹；拆镜 |
| **行走崩坏** | 行走是最难的动态 | 缩短行走距离；改用固定机位让他走入画；或切成静态姿态 |
| **打斗拆镜后不连贯** | 独立生成的动作无法对齐 | 用同一锚点动作做匹配剪辑；或一次生成完整打斗段落 |
| **关键帧一致性导致编造** | 模型为凑合关键帧而虚构中间内容 | 减少关键帧密度；只锁首尾 |
| **物理状态锚丢失** | 湿/破/脏等状态中途消失 | 每镜重复携带状态 |
| **短台词出现填充音** | 台词太短，模型补语气词 | 台词给足；或改为无对白只做反应 |
| **空间感知失败**（门、桌、走廊） | 空间几何不明确 | 写 GEO 空间布局块；明确参照物与相对位置 |
| **帧率漂移 / 逐帧重复** | 输出帧率与预期不符 | 交付前做帧级抽检 |

### 帧级复核是必须的

不要只看首帧和末帧。**逐帧或每秒抽检**，重点看：

- 动作是否完整（有没有在结果前被切）
- 手部与物体的接触是否真实
- 角色身份是否在中途漂移
- 是否有突然的跳帧或重复帧

### 交付前自修复

在交给用户之前，先自己过一遍上面的清单。**能自己发现的问题不要留给用户。**

## 第三部分：与 DUMIK 的衔接

本文是**诊断层**，不改变创作流程。使用时机：

```
写提示词时 → 用第一部分（五根柱子、眼睛、状态而非过渡）
生成之后   → 用第二部分（6 轮诊断、失败模式表）
交付之前   → 帧级复核 + 自修复
```

与 `video-methodology-mcsla.md` 的关系：那边管「怎么写对」，本文管「怎么演对」和「怎么查错」。

与 `directing-design.md` 的关系：那边管单镜的观看关系与光色，本文管画面里的人是否可信。

**冲突处理**：产品任务优先保证结构与证据，表演方法只在出现人物时启用；无人物镜头跳过第一部分。

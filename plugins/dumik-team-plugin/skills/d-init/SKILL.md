# 项目入口生成与维护

`AGENTS.md` 是项目日常工作的总控；本 skill 只负责把适合该项目的规则写进去。`design.md` 保存视觉设定，专业 skills 提供方法和执行能力，不再新增调度 skill。

## 会话级自动更新

更新返回新安装目录时，重新定位并读取新目录的本技能、路由及适用参考；不继续使用旧缓存路径。同一会话已检查则不重复运行，恢复上下文不视为新会话。


仅维护项目规则或只生成入口文档时跳过本节，避免文档任务触发插件更新。完整工作台初始化在本会话尚未检查 DUMIK 更新时，运行当前 `SKILL.md` 所在目录向上两级的 `scripts/update_dumik_plugin.ps1`；无论成功或失败，本会话后续 DUMIK skill 都不重复运行。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<插件根目录>\scripts\update_dumik_plugin.ps1"
```

返回 `current` 或 `updated` 时静默继续；返回 `skipped` 表示保留了本地定制、未拉取远端或重装，不得称为已更新。同一会话只提示一次“已保留本地定制，本次跳过自动更新”，继续任务，不自动提交、暂存或回退改动。失败时只提示 `本次未能自动更新 DUMIK Team Plugin，将按当前本地版本继续。`，随后继续当前任务。此动作只维护本地插件，不代表用户授权图片或视频生成，也不改变费用确认与批量闸门。

插件提供可复用方法，项目文件保存本项目的实际工作方式。插件更新不自动覆盖项目规则，维护一个项目也不顺带修改其他项目或全局默认。

## 触发

按 [插件路由](../../assets/agent-skill-routing.md) 仅处理项目入口需求；普通追改的恢复使用 [任务状态合同](../../assets/task-state-contract.md)，不重新初始化项目、不自动改钩子。

- 初始化工作台 / 初始化项目 / 新仓库初始化 / 装好插件怎么开始。
- 进入任务时发现项目根缺 `AGENTS.md` 或 `design.md`，且用户要开展项目制工作。
- 用户要求把协作或调度规则写进项目 `AGENTS.md`，或调整该项目的判断分工、确认方式、任务推进和工具入口。

不触发：入口文件齐全且没有规则维护要求的日常任务；直接按项目 `AGENTS.md` 执行。仅讨论改法时停在方案，不把讨论内容当成已确认规则。

## 硬规则

- **只问影响写入的缺项**：初始化新项目且类型未知时问图片 / 视频 / 混合；项目路径、类型和工作方式已知时不重复问。维护现有规则不要求重新确认项目类型。
- **项目根就是用户指定的项目文件夹**，项目身份由文件夹本身确定。不生成、不读取任何指针文件：`CURRENT_PROJECT.md` 已废弃，`CONTEXT.md`、`CLAUDE.md` 也不再生成。
- **初始化只补缺，维护只改相关项**。初始化遇到已有入口跳过；用户明确要求维护时先读原文再局部修改，保留无关条目及项目差异。只有明确重置才整份替换，替换前留底。
- **总控写在项目，不复制一套全局总控**。判断分工、选图与写词的衔接、继承已有决定、何时询问、输出与复用边界写入项目 `AGENTS.md`。模板只提供起点，不强制固定图数、机位、审批阶段或汇报格式。
- **规则与内容分开**。产品、场景、角色的具体设定及来源写入 `design.md`；单张图和当前系列的决定留在制作任务。不把白底图、局部选片或单次反馈推成全项目视觉标准。
- **完整初始化登记项目级加载钩子**。钩子只补充 `design.md`，不重复读取或注入由宿主原生处理的 `AGENTS.md`。只作用于选定项目，不在插件或用户全局注册自动扫描；保持已有钩子与信任设置不变。仅维护规则或明确只写入口文档时不额外安装，除非用户也要求钩子。
- 默认参考只来自项目 `design.md` 和 `设定集`；其他位置的文件只有用户明确给出时才可用于本次任务。
- 白底图只能用于确认产品外观、结构、颜色、丝印和配件关系；不得据此填写或推断场景、台面、背景道具、整体风格、光线、色温、构图、机位、文案排版等“统一视觉方向”。
- 不写 API Key 进任何仓库文件；Key 只进本机 `CODEX_HOME\dumik-team-plugin\api_settings.py`。

## 维护现有项目

1. 读取该项目的 `AGENTS.md` 和相关 `design.md` 内容，以及用户本次明确的调整。只为解决实际冲突读取相关设定素材，不扫描其他项目。
2. 将协作与调度调整定位到 `AGENTS.md` 现有条目；视觉设定改动定位到 `design.md`。有同义条目就合并或替换，不反复追加相互冲突的禁令。
3. 用差异修改保留本项目已有安排。用户只调整一个确认环节时，不重置候选数、场景、目录或其他协作方式；不把维护要求转成全局插件修改。
4. 回读确认规则能用于实际任务，特别检查已有决定是否继续有效、局部反馈是否被错误扩大、生成授权是否被保留。交付具体改动和仍存在的冲突。

该分支不调用项目初始化脚本，不重建目录，不初始化 API 缓存，不探测生成接口，也不要求先做图片或视频。只生成入口文档或只解释规则时也采用这一边界，不因通用环境协议中的项目制条件额外部署。若用户同时要求这些工作，按其明确范围另行处理。

## 初始化新项目

### 1. 确定现状与缺项

项目根就是用户指定的项目文件夹。用户已在具体项目目录中时，直接使用该目录，不嵌套创建 `project/<项目名>`，不重复问已知项目名或类型；不写、不读项目指针。

检查 `AGENTS.md`、`design.md` 是否存在；只有类型不明且影响创建目录时才问。运行当前宿主的插件列表命令（Codex：`codex plugin list`；ZCode：`zcode plugins list`）定位当前安装的插件，不写死缓存版本。

### 2. 生成入口文件（缺哪个补哪个）

按 [references/entry-templates.md](references/entry-templates.md) 结合项目实际情况裁剪，不逐字套模板：

- `AGENTS.md`：本项目的判断分工、任务推进、确认与授权、参考边界、工具入口和规则维护方式。图片、视频和混合项目共用一个总控段，按需要保留专业能力入口。
- `design.md`：项目视觉设定模板，记录产品、场景、角色及确认状态。

项目根的说明入口只有这两个文件。不另建 `agent.md`，不建 `CLAUDE.md`，不建项目指针或历史文件；完整初始化所需的加载钩子放在对应宿主的项目配置目录内（Codex：`.codex`；ZCode：`.zcode`）。

### 3. 登记加载钩子并读取当前上下文

两份入口文件就位后，在完整初始化或用户明确要求钩子时执行：

```powershell
node "<当前插件目录>/skills/d-init/scripts/install-project-context-hook.js" --project-root "<当前选定项目的绝对路径>" --host auto
```

- `<当前插件目录>` 来自前面的插件列表命令；项目根来自当前选定项目，不按相似目录或祖先文件猜测。
- `--host` 取 `auto`（默认，按是否存在 `ZCODE_` 环境变量判断宿主）、`codex` 或 `zcode`；判断不可靠或需要预装另一宿主时显式传入，不靠猜。
- 脚本按宿主写入：Codex 合并项目 `.codex/hooks.json`；ZCode 合并项目 `.zcode/config.json` 的 `hooks.events.SessionStart`，并把 `hooks.enabled` 置为 `true`。两种宿主都在各自配置旁放置独立加载器，同一项目可各装一套、互不覆盖。先验证脚本输出与真实文件；重复执行不重复注册，有用户自定义冲突时不覆盖。
- ZCode 中 `hooks.enabled` 已被显式设为 `false` 时，脚本直接报错退出且不改写该设置；此时向用户说明这是有意关闭的运行时开关，需先由用户启用。
- 当场通过真实工具读取 `design.md`；`AGENTS.md` 若已由原生机制加载且未变化，不再重复读取，本次新建、改动或尚未加载时才补读。不能声称刚安装的 `SessionStart` 已在本会话追溯执行。
- 钩子在后续 `startup`、`resume`、`clear`、`compact` 事件只补充读取 `design.md`，不每条消息反复注入，不重复注入 `AGENTS.md`，也不自动加载图片。
- 项目配置及钩子需要宿主信任。Codex 首次按 `/hooks` 提示由用户审阅确认；ZCode 未信任时状态为 `workspace_hooks_pending_trust`，由用户在客户端确认或用 `zcode hooks trust` 授权。两种宿主都不自动写入信任记录、不修改权限、不绕过检查；未见宿主真实触发时只报告“已配置，自动触发待首次信任确认”。

详细边界和测试见 [项目上下文钩子](../../hooks/README.md)。只有加载能力，不增加调度层；若 Node 或当前客户端钩子能力不可用，保留入口并当场读取，明确报告钩子未生效。

### 4. 按项目类型补目录

用户要求初始化当前项目时，直接按已知项目类型补必要目录；只写入口文件的请求不额外建目录。目录默认见 `assets\project-env-protocol.md`，已有项目以自身规则为准。

确需使用 `d-image-runner` 或 `d-video-runner` 的 `init_project.py` 时先检查参数，显式传项目路径。混合项目指向同一根目录，不自动搬迁旧资料。

### 5. 按需初始化环境

- 完整工作台初始化需要时，跑插件根 `scripts\init_api_cache.py` 初始化本机 API 缓存（已有则跳过）。
- 按实际项目类型轻量检查 Python、关键脚本、缓存可读；视频需要时加查 `dreamina` CLI。只创建入口文档不需要检查生成接口。
- 缺 Key/登录这类自动修不了的，列进"待用户补"清单，不阻塞完成。

### 6. 核对与交付

核对文件、真实路径和专业入口可用；确认没有把产品设定塞进总控规则。简要说明生成或跳过了什么；安装钩子时区分配置完成、脚本验证和宿主触发状态，确有待补项再列出；不强制输出全套检查表。

## 升级已有工作台

用户要求升级老项目时，沿维护分支，把仍需的调度职责并入 `AGENTS.md`，移除失效入口。保留该项目的协作习惯，不整份套回模板，不在插件更新时批量重写项目。

## 交接

- 日常任务直接读项目 `AGENTS.md`、`design.md` 和相关 `设定集`，不再次调用本 skill；`assets\agent-skill-routing.md` 仅作能力目录。
- 项目入口、默认目录和环境规则：`assets\project-env-protocol.md`。

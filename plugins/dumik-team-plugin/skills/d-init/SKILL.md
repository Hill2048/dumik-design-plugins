# 项目初始化与增量同步

**一个产品一个项目文件夹，文件夹本身即完整上下文。** 本 skill 负责把标准目录和三份核心文档（`AGENTS.md`、`design.md`、`project.md`）一次性建好并串通；初始化完成后，日常任务直接读项目根三份文档推进，不再反复补充背景。

## 参考文件硬门槛

本 skill 必须遵守 [参考文件读取硬门槛](../../assets/reference-loading-protocol.md)。开始初始化或维护前，先运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<插件根目录>\scripts\compile_reference_pack.ps1" -Skill d-init -Mode <init|maintain> -ProjectRoot <项目绝对路径>
```

读取脚本返回的 `output_path` 后，再写或改项目文件。仅做文档初始化或规则维护时，跳过插件自动更新与生图接口检查。

## 一、标准项目文件夹结构（零本地 JSON 尾气）

```text
<项目文件夹>/
├── AGENTS.md                 # 极简规约 + @[design.md](design.md)（防超 24KB 截断）
├── project.md                # 唯一项目总账本：飞书源、卖点提纯、第0~3批清单与实时状态（按需查阅）
├── design.md                 # 全案视觉宪法：白底结构锁、材质光学公式、光影母体、硬禁令
├── 素材/
│   ├── 实拍原图/             # 根目录散放实拍图自动归整至此
│   └── 飞书画布/             # 仅在需要时下载画布内非竞品关键参考图
├── 设定集/
│   ├── 白底图/
│   ├── 里程碑/
│   └── 必渲特写/
├── 制作/                     # 保持按需建子目录，绝不预建空文件夹；动工画面写 prompt.md
└── 成品/
    ├── 详情_790xn/
    ├── 主图_3x4/
    └── 入口与SKU_1x1/
```

禁止创建跨项目指针文件（`CURRENT_PROJECT.md`、`CONTEXT.md`、`CLAUDE.md` 已废弃），禁止创建带时间戳的嵌套 `project/` 子目录，禁止往项目内写入任何 `.json`、`拆解清单.md` 或 `运行记录`。

## 二、一键初始化与增量同步（`scripts/init_dumik_project.py`）

### 1. 新项目一键建档

用户指定新建文件夹、放入实拍图并给出（或暂未给出）飞书链接时，直接运行：

```powershell
python "<插件根目录>\skills\d-init\scripts\init_dumik_project.py" `
  --project-root "<项目绝对路径>" `
  --feishu-url "<飞书链接（可选）>" `
  --white-bg "<白底图路径（可选，可多次传入）>"
```

脚本会自动完成：
1. 建齐标准四目录（`制作/` 保持空，不预建空子文件夹）；
2. 将顶层散放的实拍图自动移入 `素材/实拍原图/`（重名自动避让，不覆盖）；将显式传入的白底图拷入 `设定集/白底图/`；
3. 若传入飞书链接或画板 token，直接调用 `d-visual-plan/scripts/parse_feishu_canvas.py` 拆解多画布并生成精炼版 `project.md`（若同时传 `--download-assets`，下载关键非竞品图进 `素材/飞书画布/`）；
4. 若暂未传飞书链接，生成含实拍盘点与第 0~3 批骨架的初始 `project.md`；
5. 补齐 `AGENTS.md`（仅原生内联 `@[design.md](design.md)` 防爆 `24KB` 上限，体量控制在 1.2KB 内；`project.md` 按需读取）与 `design.md`（建议锁定后精简保持在 `15KB` 内）。

### 2. 飞书画布增量同步（`--sync`）

当用户说「运营改了飞书画布，同步一下」时，在原项目目录运行：

```powershell
python "<插件根目录>\skills\d-init\scripts\init_dumik_project.py" --project-root "<项目绝对路径>" --sync
```

`--sync` 会自动从已有 `project.md` 读取 `- 飞书源：` 重新拉取画布比对更新，并**严格保留已有 `已锁定`、`已定稿`、`候选已出`、`提示词就绪` 状态及 `design.md` 内全部已定调内容**，不冲掉现有工作成果。

### 3. 可选 Codex / ZCode 会话钩子

默认面向 Antigravity 通过根目录 `AGENTS.md` 原生 `@` 内联自动加载上下文，无需额外装钩子；若用户同时在 Codex 或 ZCode 中打开该项目，可附加 `--host codex` 或 `--host zcode` 注册 `hooks/load-project-context.js`（已兼容同时加载 `design.md` 与 `project.md`），首次触发前仍需宿主侧信任确认。

## 三、维护已有项目规则

1. 用户要求调整该项目的确认习惯或写作规则时，先读取该项目 `AGENTS.md` 与 `design.md`，做最小局部修改；不把单次局部反馈推广为全案风格修改，不跨项目传播设置。
2. 纯建档、增量同步与规则维护均**不触发**付费生图接口或环境探测；若后续需补充视觉翻译整理（把飞书文案转成物理画面证据），交 `d-visual-plan` 完善 `project.md`。

## 四、初始化标准提问流程（先要飞书策划建档，再抛视觉场景清单）

- **建档前先核对 2 件事（尤其主动要飞书策划链接）**：
  1. **项目路径**：用户已在目标目录工作时直接用当前目录，缺路径时再问路径；
  2. **飞书策划链接（必问）**：若用户发起初始化时**尚未提供飞书策划文档/画布链接**，**必须先主动向用户要飞书策划链接**，拿到后再通过 `init_dumik_project.py --feishu-url ...` 拆解画布生成完整 `project.md`（若同时缺少白底图可一并提醒补充）；**只有用户明确回复“暂时没有飞书策划/先用纯实拍起步”时**，才先建无飞书骨架版 `project.md`，后续补链接再走 `--sync`。
- **建档落地 `project.md` 后，必须立刻主动抛出「视觉与场景拍板清单」**（不限于以下角度，按当前产品品类精简成 5~6 个一眼能答的问题，避免建完档就哑火、后续跑偏再返工；用户答完后立刻落进 `design.md`、`project.md` 与 `AGENTS.md`）：
  1. **参考库与材质红线**：有没有现成的 Eagle 参考库文件夹或对标实拍图？有没有明确禁用的材质（如禁木纹、禁大理石）以及偏好的同色替代材质（如焦糖真皮、亚麻、微水泥、烤漆、拉丝金属等）？
  2. **情绪基调与真实感标准**：整套画面要传达什么情绪（晴朗上午暖阳积极感、安静松弛感，还是暗调高反差）？偏**真机随手拍大景深微颗粒**，还是**商业精修棚拍**？
  3. **多使用/饮用场景矩阵（防单调）**：按产品真实一天的使用链路，全页要拆成哪几个不同生活场景（例如杯具：意式咖啡机直萃、餐桌早餐、办公书桌、客厅阅读、通勤装包、水吧冲洗等），避免全案挤在同一张桌面上？
  4. **人物设定与逐屏人物判定**：是否需要锁统一主角人物身份卡？全页哪些屏真人半身/侧颜、哪些屏局部手部/衣袖交互、哪些屏刚离席生活余温、哪些屏纯无人物微距？（确定后凡含人物/手/袖特写均强制垫人物卡）
  5. **概念屏与实景屏边界**：哪些对比/机制屏（如材质金字塔、结构剖面）只迁项目配色、不带室内场景？是否有极少数需画内结构字的屏（其余统一纯无字底图）？
  6. **执行渠道、默认模型与抽卡习惯**：默认走 DesignFlow MCP 还是直连脚本？默认模型（如 `Banana 2.1`）、默认抽卡数量（如 `x2`），以及是否约定未明确申明不切其他模型？
- 详细模板规范见 [references/entry-templates.md](references/entry-templates.md)。

# 入口文件模板

本模板是项目入口的起点，不是每个项目都必须遵循的固定流程。初始化只补缺；维护已有项目时保留原文，只修改用户要求的相关条目。

项目根就是用户指定的项目文件夹，根目录只保留 `AGENTS.md` 和 `design.md` 两个说明入口。不生成 `CLAUDE.md`、`CURRENT_PROJECT.md`、`CONTEXT.md`：项目身份由文件夹本身确定，不靠指针或历史文件记录。完整初始化另在项目 `.codex` 内登记只读加载钩子，按 `d-init` 的安装步骤合并，不创建全局扫描器。

项目 `AGENTS.md` 承担日常总控，`d-init` 只负责生成与维护。按用户已确认的工作方式和图片 / 视频 / 混合类型裁剪下面的单一总控与能力入口，不叠加图片总监、视频总导演或额外调度 skill。

## AGENTS.md 模板

```markdown
# 项目协作与执行

## 沟通与执行

- 中文、简洁；已确定的不重复问，不强制每次汇报流程。
- 文件操作和执行必须使用真实工具，核对后再报告结果；不把提交成功当成交付完成。
- 不覆盖原始素材，不编造产品结构、参数或卖点；实际生成和外部写入须有用户要求。

## 项目总控

- 本文件规定本项目的协作、任务推进与调度方式；专业 skills 提供方法和执行能力。项目明确安排优先于其默认协作流程，技术限制、真实输入与执行授权仍须遵守。
- 用户决定表达方向和重要取舍；助手整理依据、提出推荐、写提示词并完成获准执行。已有设计直接落实，需要探索时再提出方案，不为走流程重新策划。
- 先继承本任务有效的已确认内容，再处理本次变化。新增图片先判断是补充、替换还是新目标，不因新图自动清空已定内容；换项目、产品或发生冲突时只重看受影响的部分。
- 画面理解、选图与写词共同推进。参考图按用途取用，不固定角度、图数或方案数；需要用户判断时展示必要证据与关键差异，不把内部准备工作变成强制审核表。
- 能自己读取、比较、验证的先完成。只有新的关键取舍、冲突、必需依据缺失或超出授权才提问；已确认的方向与已明确的执行范围不重复确认。
- 用户指着当前图要求修改，已指定本次目标，不再问一次使用许可；该用途不自动推广到其他任务。用户可只看变化说明，模型收到的提示词和实际图片仍须完整自洽。
- 按已准备好且获准执行的任务推进，不为固定关卡重新探索方向。核对可验证偏差、保留候选，审美由用户判断；未经授权不追加付费生成、修复或重抽。
- 系列与单图决定跟随制作任务，记录结论、适用范围及相关来源或版本。局部反馈不自动变成项目标准，不另建复杂状态系统。

## 文件分工与参考

1. `AGENTS.md`：本项目总控与规则。
2. `design.md`：产品、场景、角色的视觉设定及确认状态。
3. `设定集`：与当前任务相关的已确认素材。

- `AGENTS.md` 由 Codex 原生项目指令机制加载；完整初始化可配置项目 `.codex/hooks.json`，在会话启动、恢复或压缩后只补充加载 `design.md`，首次仍需钩子信任确认。初始化当场或钩子未生效时按需用真实工具读取；`AGENTS.md` 已加载且未变化时不重复读取，也不把钩子配置存在当成已经触发。
- 默认只从 `design.md`、相关设定素材取参考；其他位置只使用用户明确给出或已明确允许在当前任务、系列继续使用的文件。不自动扫描素材、制作、成品或外部素材库找参考。
- 白底图只确认产品外观，不填场景和统一视觉方向；场景、角色素材只按各自的确认用途使用。
- 用户允许当前任务使用外部文件，不等于允许把它纳入设定集。只有明确确认长期用途后才归入设定集并更新 `design.md`。
- 图片候选、提示词与运行记录落 `制作/图片/<任务名>`；视频及其关键帧落 `制作/视频/<任务名>`。确认 OK 后进入对应 `成品`，不自动成为基础设定。

## 专业能力入口

调用前运行 `codex plugin list` 定位当前 DUMIK 安装目录，再读取对应 `skills/<技能名>/SKILL.md`。不写死缓存版本；插件 `assets/agent-skill-routing.md` 仅作能力目录，项目协作方式以本文件为准。

| 当前需要的能力 | 入口 |
| --- | --- |
| 卖点顺序、策略或方向探索 | `d-visual-plan` |
| 图片画面、参考取用、提示词、局部修复判断 | `d-image-director` |
| 参考图反推提示词（人先判主次） | `d-prompt-reverse` |
| 原图与生成图结构验收（一致/不一致/无法判断） | `d-consistency-check` |
| 生图、改图及图片后处理 | `d-image-runner` |
| 视频分析、分镜、关键帧要求与视频提示词 | `d-video-director` |
| 实际生视频 | `d-video-runner` |
| 已授权的成组任务编排 | `d-project-pipeline` |
| 初始化或维护项目规则 | `d-init` |

- 只调用本次真正需要的专业能力，不强制经过所有入口，也不因已有提示词就自动生成。
- 视频关键帧与详情页共享产品依据和图片准备方法；生视频只补充所需动态要求，静态图通过不自动代表动态通过或生视频已授权。
- 使用本机配置保存凭据，不把密钥写进项目文档、提示词或运行记录；接口动态项在实际调用前检查。

## 规则维护

`d-init` 只在初始化或用户要求调整规则时维护本文件，日常执行直接遵循这里。项目协作变化只局部更新本文件；具体视觉设定仍放 `design.md`。插件升级不自动覆盖项目定制，也不把一个项目的选择传播到其他项目。
```

按项目类型删去不需要的能力和制作目录；保留用户明确指定的沟通、探索、确认、输出和复用方式。没有确认的偏好不写成事实，不强制固定候选数、角度表或分阶段审批。

维护时保留现有项目结构和有效规则，优先修正实际冲突，不追加第二套总控章节。

## design.md

```markdown
# 项目视觉设定

- 产品外观：待确认
- 场景：待确认
- 角色：待确认
- 设定素材：见 `设定集`
- 状态：尚未确认；用户确认后记录来源和日期。

## 设计语言

> 只记本项目已确认的视觉约束；未知项保持「待确认」，不按品类名臆造。

- 允许风格：待确认
- 禁止风格与元素：待确认
- 产品清晰度优先级：待确认（例：结构与 Logo 区 > 氛围装饰）
- 控制区与自由区默认：待确认（例：产品结构锁死；场景氛围可发挥）
- 系列固定规则：
  - 情绪：待确认
  - 光：待确认
  - 色结构：待确认
  - 镜头气质：待确认
  - 限制：待确认
```

未知的产品参数、材质、配色、光线、画幅和时长均标为待确认，不根据项目名称编造。引用具体设定文件路径，区分探索候选和用户确认的标准。

白底图只能用于确认产品外观、结构、颜色、丝印和配件关系；不得据此填写或推断场景、台面、背景道具、整体风格、光线、色温、构图、机位、文案排版等“统一视觉方向”。统一视觉方向只接受用户明确确认的文字设定、场景图、角色图、KV 或其他能表达项目视觉方向的素材。

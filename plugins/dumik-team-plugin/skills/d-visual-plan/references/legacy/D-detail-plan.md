# 详情页出图策划

本方法解决“要证明什么、按什么顺序证明、怎样形成视觉证据”。项目 `AGENTS.md` 决定何时调用；用户已有方案的部分直接作为输入，不要求每次从策划开始。

这是图片线的转化策划入口，对称于视频线的 `d-visual-plan`：视频管卖点顺序和证据链，这个 skill 管详情页的卖点顺序、视觉证据和创意方向。

## 执行边界

默认只输出文字：视觉设定、详情页结构、每卖点视觉证据策略、创意方向。不写最终可提交的抽卡提示词，不调用 `d-image-runner`、图片 API 或任何生图工具。

- 用户要把单个卖点发散成四宫格抽卡或量产候选：交给 `d-image-director`。
- 用户要把已选定的方向写成可复制改图指令：交给 `d-image-director`。
- 用户明确说生图、出图、调用接口：交给 `d-image-runner`。
- 抽卡选片后产品细节偏了：交给 `d-image-director`。

## 第一步：视觉设定

读取当前任务有效的产品、场景与表达依据。它们的确认状态和复用范围由项目总控提供，本方法不重新判断是否升为项目标准。

视觉设定来源只有两类：

1. 当前项目 `design.md` 中已确认的文字，以及 `设定集` 中与当前任务相关的文件。
2. 用户本轮明确提供的产品描述、附件、路径或点名文件。

不得从 `素材`、`制作`、`成品`、Eagle 或其他外部素材库自动扫描、挑选或补齐参考。用户给出的设定集外文件只用于本次任务；用户确认纳入项目设定后，才归入 `设定集` 并更新 `design.md`。

白底图只能用于确认产品外观、结构、颜色、丝印和配件关系。不得从白底图的白背景、棚拍光、留白、机位或摆放方式推断项目的视觉调性、场景母版、光线标准、构图标准或文案排版；这些项目没有独立的用户确认依据时必须保留待确认。

可供策略参考的信息包括下列内容；未知项保留未知，记录到哪里及是否写回由项目总控决定：

- 视觉调性一句话：只从用户明确确认的文字方向、场景图、角色图、KV 或其他方向性素材中提炼；不能从产品白底图提炼。确认后放在视觉设定最前面，作为全套图的弱牵引，不锁死构图，也不压过产品身份锁。
- 产品身份锁：轮廓与比例、把手与握柄、盖子或顶部结构、五金（阀、钮、扣、铰链）、品牌或 logo 区、材质工艺、SKU 专属色与细节。
- 产品白底图引用：哪一张 `设定集/白底图` 文件是产品结构基准，用于后续抽卡引用和细节修复对照。用户本轮明确给出的白底图也可临时使用，但不自动纳入设定。不要叫它“真值图”，统一叫“产品白底图”。
- 材质语言：每种材质在光下的可见表现，不要停在材质名。例如纯钛写成“克制银灰、低饱和、冷调工业感、干净边缘”；乌檀木写成“深色木纹走向、哑光、纹理可见但不抢主体”。
- 场景母版：详情页统一的背景、台面、光线基调，让全套图视觉一致。
- 参考图角色：产品白底图提供产品结构与外观，场景图提供已指定的环境属性，KV 提供已指定的表达或版式信息；不得把白底图兼作场景母版。只使用本次需要且已明确用途的素材。

视觉设定是数据文件，不是提示词。它描述“产品是什么样、不能漂移哪里”，不描述某一张图的构图。

## 第二步：详情页结构与卖点编排

吃运营给的卖点清单，先解决信息顺序，再谈画面。

先内部回答：

1. 用户进详情页第一眼要先理解什么？
2. 接下来最可能怀疑什么？
3. 哪个可见证据能消除这个怀疑？
4. 哪个使用利益值得优先记住？
5. 详情页结尾要留下什么品牌记忆？

编排规则：

- 一个卖点对应一个画面任务，不要一张图塞多个卖点。
- 强卖点优先，砍掉不改变认知或决策的弱卖点。
- 详情页是一条转化序列：先认知，再信任，再使用愉悦，再差异化，最后品牌收尾。

## 第三步：每卖点的视觉证据策略

这是这个 skill 的核心产出，也是下游抽卡的蓝图。对每个保留的卖点，写清：

- 卖点要证明的判断：一句话，用户看完该信什么。
- 视觉证据：用什么可见的场景、动作、对比、细节特写来证明。把抽象卖点翻成可见画面，例如“耐用”写成“刀在板面剁击、板面无明显刀痕的特写对比”，而不是写“耐用”。
- 画面角色：主体是产品、人手、材质特写、使用场景还是对比关系。
- 表达方向：根据任务需要提出有意义的视角、场景或对比差异，不为固定方案数凑方向；产品身份不随表达变化。
- 比例依据：这个卖点画面用什么比例，依据是什么（详情页通用竖版、对比图、特写）。

## 输出

返回：

1. 视觉设定状态：复用已有 / 本次从设定生成 / 缺设定需补。
2. 详情页核心转化障碍。
3. 卖点模块顺序表：模块、卖点、要证明的判断、主视觉证据。
4. 本次需要的视觉证据策略与表达方向。
5. 交接说明：哪个卖点先抽卡，怎么交给 `d-image-director`。

## 交接

- 将本次需要展开的卖点、视觉证据和方向交给 `d-image-director`；是否采用四宫格由项目任务决定。
- 编排顺序一旦确定就锁住；下游发散提示词时不重新设计详情页结构，只在单个卖点内展开。
- 视觉设定路径要一并交给下游，让抽卡引用同一份产品身份。

## 策略交付的边界

本方法只交付策略与证据分析，不把一次试跑、选片或技术经验自动写入 `design.md`。反馈范围、长期复用与规则维护统一遵循项目 `AGENTS.md`；调用本方法不产生额外的项目级回写阶段。

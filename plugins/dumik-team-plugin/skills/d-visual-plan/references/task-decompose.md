# 模糊需求任务拆解

进入卖点/详情/视频策略或向 `d-image-director` 交 brief 之前，先把口语需求拆成五格。缺格标「待确认」，不编造。

## 五格

| 格 | 问题 | 电商例子 |
| --- | --- | --- |
| 目标 | 这张/这页要让人相信或做什么 | 主图第 3 张证明「0 夹层」 |
| 主体 | 画面英雄是谁 | 纯钛菜板本体 |
| 关系 | 主体与人/场景/道具/证据如何相处 | 剖面对比放右侧；无人物 |
| 约束 | 不可改、不可出现、画幅、系列规则 | 结构锁；禁乱字；2:3；冷静专业 |
| 标准 | 怎样算完成 | 结构验收无「不一致」；卖点一句可读 |

## 强制动作

1. 用户一句话需求 → 先填五格（可短）再写策略或 brief。
2. 项目存在 `design.md` 时：**先 Read 设计语言段**，把允许/禁止风格、清晰度优先级、系列规则并入「约束」。
3. 设计语言为「待确认」时：策略里列出待确认项，不擅自定品牌调性。
4. 五格与策划画板冲突时：以最新轮策划 + 用户当场指示为准，并记下差异。

## 输出模板

```markdown
## 任务拆解
- 目标：
- 主体：
- 关系：
- 约束：（含 design 设计语言要点 / 待确认）
- 标准：
```

## 交给下游

- 缺的是卖点顺序/证据链 → 继续本 skill 的 image/video 模式。
- 五格已清且只要画面提示词 → `d-image-director`（brief 或 edit）。
- 只要反推参考图提示词 → `d-prompt-reverse`（须人先判主次）。


## 与策划画板的映射

| 五格 | 画板上常见块 |
| --- | --- |
| 目标 | 「运营想解决什么」+ 本轮主图意图 |
| 主体 | 产品信息 / 白底 |
| 关系 | 主图每张「标题+证据」关系；详情模块顺序 |
| 约束 | 设计语言、画幅、禁人物等 |
| 标准 | 可验收：证据是否出现、结构是否漂 |

## 反例

- 只写「做一套高级主图」→ 五格全空，禁止进入卖点编造。
- 从白底脑补生活方式故事填「关系」→ 标待确认，等场景参考或用户确认。

# 高清修复工作流

这是一个**三次生图 + 一次提示词提炼**的固定流程。不要跳步骤，不要把它改写成普通改图，也不要把“请反推提示词”的请求句当成最终画面提示词。

## 适用情况

- `image2` / `banana` 系列图片反复修改后变脏、发灰、边缘糊、材质脏、细节丢失。
- 用户明确要“去渍”“恢复高清”“按那篇公众号的方法来”。

## 输入边界

- 待修原图必须来自项目 `设定集`，或由用户本轮明确上传、给路径或点名使用。
- 不得从 `素材`、`制作`、`成品`、旧任务或外部素材库自动找图，也不得用文件名、修改时间或目录顺序替用户选图。
- 本流程生成的线稿和色稿只作为当前这次高清修复的中间输入，不自动升格为项目参考或写入设定集。

## 固定四步

### 第一步：提取线稿

必须先调用 `D-image-run` 的真实执行脚本，把原图转成干净黑白线稿。

- 目标：固定造型、结构、边缘。
- 默认模型：`image2`
- 默认画质：自动换算为合法的 `image2` 尺寸（长边 2048）
- 线稿提示词要强调：
  - 只保留黑白两色
  - 线条干净流畅
  - 去掉杂色、渐变、灰脏感
  - 保持原图结构和比例不变

### 第二步：提取色稿

调用 `D-image-run` 生成干净的固有色色稿，不保留线稿、阴影、渐变和材质纹理。

- 目标：只保留各物体固有色和色块关系，保证物体之间固有色对比层次清晰。
- 默认输出：`02-color-draft.png`

### 第三步：提炼真实中文画面提示词

基于原图反推一份中文提示词，重点提取：

- 主体和造型
- 材质
- 光影
- 色调
- 场景或背景
- 构图与镜头感

如果用户已经给了可用提示词，优先复用并轻量补全，不要强制重写。

不能只保存“请根据原图反推出一份中文提示词”这类指令；必须得到一段描述当前画面的成品提示词。

### 第四步：高清修复

再次调用 `D-image-run` 的真实执行脚本，输入：

- 原图
- 第一步线稿图
- 第二步色稿图
- 第三步真实中文画面提示词

最终修复提示词要明确：

- 按图片1还原线稿结构
- 按图片2恢复固有色和光影
- 保持主体造型和比例稳定
- 输出高清、干净、无脏污、无灰感、边缘清晰的最终图

默认模型和参数：

- 默认模型：`image2`
- 默认画质：自动换算为合法的 `image2` 尺寸（长边 2048）
- 用户明确要更高档位时：再单独指定更大的合法 `image2` 尺寸

## 执行入口

优先执行脚本：

`scripts/run_image_repair_hd_workflow.py`

最小调用形态：

```powershell
python scripts\run_image_repair_hd_workflow.py `
  --image "<原图路径>" `
  --output-dir "<输出目录>" `
  --scene-prompt "<从原图提炼出的真实中文画面提示词>"
```

可选参数：

- `--scene-prompt "<真实中文画面提示词>"`（必传；兼容旧参数名 `--reverse-prompt`）
- `--lineart-model image2|banana|bananapro`
- `--color-model image2|banana|bananapro`
- `--final-model image2|banana|bananapro`
- `--final-size 944x2048` 这类合法尺寸；不传时 `image2` 自动按原图比例换算
- `--subject "<主体补充说明>"`

## 输出要求

结果目录至少要有：

- `01-lineart.png`
- `01-lineart-prompt.txt`
- `02-color-draft.png`
- `02-color-draft-prompt.txt`
- `03-scene-prompt.txt`
- `04-final-prompt.txt`
- `05-final.png`
- `repair-run.json`

## 交接规则

- 真正生图一律复用 `D-image-run` 脚本，不重写接口层。
- 如果用户只要方案不要执行，可以只输出四步结果和最终提示词，停在文字层。
- 如果用户要继续批量跑，再交给 `D-image-run` 或更上层自动编排。

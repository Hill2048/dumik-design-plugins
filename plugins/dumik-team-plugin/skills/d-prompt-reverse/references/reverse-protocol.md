# 反推协议

## 第一步：主次表（必填）

| 级别 | 本图内容 | 反推时处理 |
| --- | --- | --- |
| 主控制 | （人填：如产品轮廓、持握、主光方向） | 必须写入草稿且标锁 |
| 次要 | （如背景盆栽、桌布纹理） | 可写可简化 |
| 可忽略 | （如压缩噪声、无关边角） | 不写进 Prompt |

未填主控制栏 → 停止，向用户要优先级。

## 第二步：控制区 / 自由区

- 控制区：主控制条目 + 品牌/结构相关  
- 自由区：明确可改的氛围项  
- 不可迁移：仅该参考图叙事、不能搬到本产品的元素（别人的 Logo、错误品类）

## 第三步：结构化拆解

按需使用导演库分段顺序，输出：

1. 主体与结构锁  
2. 场景与关系  
3. 机位  
4. 光影  
5. 材质  
6. 禁止建议（本图真实风险）

## 第四步：交付标签

```markdown
## 反推草稿（非终稿）
- 主次：已由人确认 / 待确认
- 控制区：…
- 自由区：…
- 草稿正文：…
- 下一步：确认后交 d-image-director 编译终稿
```

## 禁止

- 跳过主次表直接长文 Prompt  
- 把参考图里的他牌 Logo/文案当本产品锁  
- 声称「已可直接出图」而未标人确认


## 与控制层

主控制栏应能映射到 P0/P1；可忽略栏不得偷偷写进终稿抬成 P0。反推完成后的终稿编译仍走 `d-image-director` 控制层自检。

# 图片导演

本 skill 提供图片专业方法，不承担项目总控。任务意图、有效决定、提问与确认方式由项目 `AGENTS.md` 给定；参考资料中的流程与展示范例不另设项目协作规则。

统一原 `D-image-prompt`、`D-image-HD`、`D-image-repair` 和 `D-grid-prompt` 的图片创作入口。

## 参考文件硬门槛

本 skill 必须遵守 [参考文件读取硬门槛](../../assets/reference-loading-protocol.md)。规则包会登记本 skill `references/` 下的全部文件，再追加本轮命中的条件文件；只有命中文件进入当前正文，读取完整规则包后才能分析画面或写 Prompt。不能把链接当目录，也不能以“当前上下文已经有”替代本轮读取。

Windows / 有 PowerShell 时：先运行当前插件目录的 `scripts/compile_reference_pack.ps1 -Skill d-image-director -Mode <detail|detail-macro|detail-contrast|detail-scene|edit|brief|direction|hd|repair> -Model <模型名>`，再读取脚本返回的 `output_path`。规则包没有成功生成或没有读完时，不进入画面分析。

**Grok Bot / Linux：** 若 `compile_reference_pack.ps1` 或 PowerShell 不可用，跳过编译脚本，但必须用真实文件工具直接 `Read` Mode 路由表中本轮命中的全部文件（含 `control-layer.md` 与 `prompt-contract.md`）；不得因跳过脚本而跳过参考正文。读完命中文件后再写 Prompt。

## 会话级自动更新

更新返回新安装目录时，重新定位并读取新目录的本技能、路由及适用参考；不继续使用旧缓存路径。同一会话已检查则不重复运行，恢复上下文不视为新会话。

每个会话首次触发任意 DUMIK skill 时，先运行当前 `SKILL.md` 所在目录向上两级的 `scripts/update_dumik_plugin.ps1`；无论成功或失败，本会话后续 DUMIK skill 都不重复运行。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<插件根目录>\scripts\update_dumik_plugin.ps1"
```

返回 `current` 或 `updated` 时静默继续；返回 `skipped` 表示保留了本地定制、未拉取远端或重装，不得称为已更新。同一会话只提示一次“已保留本地定制，本次跳过自动更新”，继续任务，不自动提交、暂存或回退改动。失败时只提示 `本次未能自动更新 DUMIK Team Plugin，将按当前本地版本继续。`，随后继续当前任务。此动作只维护本地插件，不代表用户授权图片或视频生成，也不改变费用确认与批量闸门。

**Grok Bot / Linux：** 跳过上述 Windows 自动更新脚本；需要更新时按宿主约定更新插件仓库，不把跳过更新当成跳过参考读取。

## 模式

选择遵循 [插件路由](../../assets/agent-skill-routing.md)；多轮追改读取 [任务状态合同](../../assets/task-state-contract.md)，先确定修改部件和当前有效属性，再写独立完整正文。模式细则以上方 **Mode 路由表** 为准。

- `detail`：项目制里程碑（`MS*`）及第 1~3 批详情页/主图/入口纯无字底图编写与追改（覆盖写入 `制作/<编号_名称>/prompt.md`）。必须完成四项动作：① **先睁眼读参考再动笔**：若 `project.md` 对应行附有 `素材/飞书画布/<编号>_参考.*`，动笔前先读取看清其构图斜率、对比张力与压字底色明暗并参考原主副标题体量定留白，但**严禁将该竞品/带字参考截图写入 `@图N` 喂给生图 API**；② 绑定自有基准图保真级（`@图1 [结构锁死]` 自有白底图、`@图2 [属性迁移：仅迁光影色温与台面质感，禁抄构图]` 自有里程碑、`@图3 [动作引导]` 仅限用户自有线稿草图）；③ 严格落实 `project.md` 指定的 `机位景别`（相邻屏不重样）与 `PS留白要求`（**车图/直通车入口图 `E01*` 强制顶部 20%~25% 干净低反差文字留白区、背景简洁不杂乱**；**展示类小件如放大镜/相框/证书托动笔前必先确认是否用于后期贴图/展示证书，若是则锁死 `0°` 正平视**）；④ 设计视线从留白压字区落向物理证据瞬态，严禁强广角畸变与任何排字/标尺/引线。
- `edit`：普通改图、多参考融合、洗图、KV、场景、材质和人物锁定。洗图遇到带竞品本体/文字/水印或比例不对（如 `1:1` 转 `9:16`）的参考图时，优先调 `scripts/wash_prep.py`（`single` / `batch`）物理色块脱壳、抹字并平滑扩充顶部留白区。
- `brief`：按任务要求构思图片视觉方向；确有策略缺项时才使用 `d-visual-plan`。
- `direction`：把给定表达展开为有意义的候选差异；四宫格是可选表现形式，不规定方向数或确认关卡。前期概念/调性探索优先用 `D-grid-prompt.md` 的「大牌杂志无缝 2×2」写法（无缝组图、无文字、金属自然反射柔和环境、参考大牌杂志组图、避开大理石与碎道具堆砌；4 格是否同景别按需自选，不强制死锁）。
- `hd`：线稿 → 色稿 → 真实画面提示词 → 高清重绘。
- `repair`：对照 `设定集/白底图/` 诊断已选图片的局部产品漂移，走「产品外扩切图（吃满 2K 分辨率，坐标支持 `0~1` 百分比免手算像素）+ `--white-slot N` 自动切五视图白底（或 `--white-box`）+ 偏差区填高对比色块（破除模型照抄惰性）+ 授权重绘（优先 **`即梦 5.5` ＞ `即梦 5.0 Pro` ＞ `Banana 2.1`**）+ 贴回多候选分层 `.psd`/`.tif`」单张/批量闭环（脚本 `scripts/repair/mask_repair.py`；设定集拼白底身份卡、大图 2K 瘦身、五视图自动框选与 10×10 标尺网格见 `scripts/prep_reference_assets.py`）。**两项防踩坑分支**：① **强透视/广角产品保透视分支**：若局部裁切会切掉桌面参考线或消失点导致杯体/产品透视反复歪斜，直接**跳过局部裁切，走整图不裁切 + 部位分色块遮罩**（如杯口与杯身用不同高对比色块精准区分）；② **非产品局部改图免垫白底**：只修背景缺口、移除杂物或在空盘加小摆件/甜点（不碰产品本体）时，**严禁硬垫产品白底图**。**防变红变糊铁律**：重修同一部位或修独立新部位一律**回到最开始的原始干净底图**切图（严禁连续串联垫上一轮 `*_已修复.png`），仅物理重叠部位才允许承接已确认修复图且最多串联 1 轮。**材质追改锚点**：调整金属或哑光部件质感时须给出「高光带宽 + 粗糙度中间态物理锚词」（如柔缎微光、多道柔和条状环境反射），禁用纯相对词导致「塑料感 ↔ 过冲高光」钟摆过冲。**极速与极简要求**：`repair` 免跑重型参考包编译与更新检查，1 轮并行看图直接出预览；确认回复硬上限 ≤5 行（只给预览图 + 一句话修哪几处 + 确认词），**禁贴整段 Prompt 代码块和技术废话**。

## 控制层检查（写 Prompt 前）

选好 mode 并读完命中参考后、动笔写 Prompt 前，必须过一遍（细则见 `references/control-layer.md`）：

1. **P0/P1/P2**：结构永不交易；品牌清晰次之；氛围可让步。
2. **结构锁（P0）**：比例、轮廓、关键部件、接口/按键、材质固有色、Logo/丝印区 — 不得重设计；看不见的标「无法从当前图确认」，不瞎补。
3. **去抽象化**：位置、机位、占比、光向、不可改项写清。
4. **控制区 vs 自由区**：锁死与可发挥必须明示。
5. **负面禁止项单独成段**：只写本任务真实风险。
6. **系列规则 / design 设计语言**：有则强制读并继承；无则标待确认。
7. **线稿分工**（有线稿时）：产品线稿锁结构，场景线稿锁构图。
8. **分段顺序**：风格→主体锁→场景→机位→光影→材质→质量→禁止（见 `prompt-segments.md`）；需要叙事骨架时再用 `six-structure.md`。

## 共同规则

- 多参考图先短写每张图的真实职责；只出现实际存在并需要控制的内容。
- **三层垫图铁律与去重（严禁误砍设定集或重复垫图）**：
  - **L1 永久真源（默认保留）**：`设定集/白底图/`、`设定集/人物身份卡/`、`设定集/场景身份卡/`、`设定集/里程碑/` 与 `成品/` 已定稿母版。
  - **L2 临时参考（按需垫入）**：干净真机实拍图、构图参考图。
  - **L3 禁用区（默认禁止垫入）**：`制作/` 目录下上一轮刚生成的未定稿候选图/废稿、带 UI/水印的飞书画布截图。
  - 用户说「不要垫图」时，**默认只清掉 L3（未定稿候选与废稿）与 L2，绝不擅自去掉 L1（白底图、人物/场景身份卡与已定稿母版）**，除非用户明确点名连设定集/母版也不要。动笔与发包前必须做**参考图去重核对**，同一资产或高度同义的图禁止重复占 `@图2` / `@图3`。
- **功能动作屏「垫场景稳风格、换摆件防呆板」四项检核**：参考飞书竞品功能图（如倒水防漏、单手轻拿、宽口清洗）时，**只拆物理动作关系，严禁照抄竞品的光秃白墙孤桌**；写实景生活/功能屏前核对四项：① **核心场景设定按需垫入稳风格**（为防止全案风格与色温飘忽，需要稳调性时正常垫入 `设定集/场景身份卡/` 核心场景母版，仅迁其光影色温、空间材质与调性，但**显式清空原图小摆件、不照抄固定道具**）；② **全案配色结构在场**（主亮区 + 暖桥色 + 深色空间锚点 + 产品主角四色齐备，禁塌成纯白/纯灰光墙）；③ **摆件每屏换新**（从 `assets.md` 风格摆件库按动线领用 1~2 件、≤3 件新鲜日用小物并回填屏号，禁跨屏反复复制同一盏台灯/笔记本/眼镜/杯垫）；④ **饮品色温层次**（严格按 `assets.md` 饮品/食材错峰排期表执行，非明确纯清水实验时优先用契合色温的透亮有色饮品替代寡淡白开水）。
- **金属/结晶材质防发粉发灰 & 防具象花纹铁律**：写高温钛结晶、锤纹或拉丝金属产品时，必须写清**高反差、致密不规则 1~2mm 冶金晶粒微面折光与清晰明暗金属体量感**，严禁泛写“哑光银/雾面灰”导致模型塌成发灰发粉廉价喷砂，也避免堆砌“雪花/冰花”字样触发模型画出具象五角雪花星形；出图质检凡发现产品金属发灰发粉、偏小或质感失真，必须如实标出缺陷并走 `即梦 5.5` 局部修复，绝不放行。
- **氛围反推 4 要素（防退化成冷硬 3D 展台图）**：从参考图拆解光影与材质氛围时，必须写清 ① 主光位与背透光晕（Halation/柔边融光）；② 镜头焦段与浅景深空气感；③ 材质微观反光（哑光/丝绒/半透，慎用易触发 3D 硬边渲染的「展台/水泥块」词）；④ 暗部色彩倾向。
- **透明玻璃去青绿与对比实验四底线**：凡出现透明容器、实验缸、护盾或展板，**严禁默认渲染出廉价普通玻璃的青绿/蓝绿切边**，必须明写「零青绿杂色的纯无色低铁光学石英水晶（切边与隔板仅呈透明白/浅暖象牙银或淡香槟折光）」并在禁止项封死发绿玻璃边；做防锈/抗腐/保鲜/保温/保冰等对比实验图时，① **对比介质与饮品必须严格控制变量（同饮品/同介质对比）**，如保温对比两边同装热拿铁、保冰对比两边同装深琥珀冰美式，严禁一边拿铁一边白开水或一边黑美式一边奶茶导致看不出对比；② **物理状态反差必须 0.5 秒一眼可辨**：防锈对比须左无色清澈净水 vs 右浑浊黄褐锈水+锈渣，保温对比须左鲜亮拉花配清晰逆光上升热气 vs 右彻底放凉 0 热气且塌泡暗沉，保冰对比须左满杯硬挺大方冰+贴沿下沉清透冷气+外壁干爽零水珠 vs 右仅剩极少量快化没的小碎冰+饮品化水变淡+外壁满是滑落冷凝大水珠与桌面水渍；③ 下方拼色基座须**严丝合缝零竖缝**、水中产品**稳坐缸底绝不悬浮**。
- **塑胶/烤漆类部件按实物光泽度精准写词（去塑料感≠乱加高光；结构锁与实拍参考分离）**：写塑胶/硅胶/烤漆类部件时，忌直写「PP / 注塑 / 普通塑料」导致灰暗廉价感；同时须严格按当前产品实物表面光泽度区分写法——**实物本身为柔和哑光/微雾面时**，用「清透提亮固有色 + 低反差柔雾暖哑光 / 亲肤粉雾纯漫反射」控住柔和度，禁写「骨瓷 / 釉面 / 亮高光」防过冲出硬白反光条；**实物本就为亮面/高光件时**，再按实拍写清光泽反射形态，严禁跨产品一刀切。**结构比例与部件厚度唯一锁死无畸变棚拍白底图**；用户提供的手机近拍实拍图（常带广角鼓胀或非目标开合态）只用于校准真实色相与表面光感并转译进文字，严禁直接替代棚拍白底当结构参考。
- **置景摆件库 & 饮品/食材排期领用制 + Eagle 自动检索**：里程碑定调后进入详情批量前，先确认 `assets.md` 已填妥 **8~12 件风格摆件库**（重点样式可先按 `multi-view-lock.md` 模板出 1×3/3×2 实物目录选样卡或调 `scripts/eagle_ref_picker.py --folder "<库文件夹>" --query "<场景词>" --project-root "<项目>"` 拍板样式入库 `设定集/摆件身份卡/`）以及 **饮品/食材错峰排期表**；写每屏 `prompt.md` 时**只从 `assets.md` 领用并回填已用屏号**（每屏摆件 ≤3 件、饮品/食材照表执行、相邻屏不重样、严禁临场反复默认咖啡或廉价杂物）；同风格人物穿搭（如母女/情侣）强制写「同配色体系 + 不同款型单品」，避免机械复制同款衣服。
- **画内结构字白名单保护**：当用户明确指定某屏需要画内结构文字（如证书铭牌、对比金字塔分层文字）时，在 `prompt.md` 顶部标注 `[画内字白名单]` 并写明缩略图级大号粗体高对比要求；后续追改必须原样保留，严禁被「纯无字底图」规则误删。
- **产品身份档案「按需摘取」与反哺（严禁把画面看不见的部位抄进提示词）**：`design.md` 的 7 维产品身份锁是全量字典，写新屏 `prompt.md` 或局部修复词时，**只按本屏实际可见视角与状态摘取对应部位**（如无盖屏不提杯盖、不拍内腔不提杯底钢印、远景不提微刻），严禁把画面展示不到的部件整段粘进提示词占用上下文或误导生图；确认新细部后反哺回写 `design.md`。
- **提示词瘦身红线**：单图正文控制在 **180 ~ 380 字（硬上限 450 字）**，2×2 四宫格 **350 ~ 550 字**（共用设定只写 1 遍，每格只写 1 句构图差）；发包正文禁用 `**加粗**`、`【】`、多级列表与括号套括号，负面句仅文末 1 句（≤5 词）；追改删旧换新不叠补丁，垫图后只写变化点不做冗长复述（细则见 `references/prompt-contract.md`）。
- **采用最小充分描述 & 产品工艺按可见部位按需调用**：写词与局部修复前须明确区分产品工艺（如平面丝印 vs 物理冲压凹印 vs 立体浮雕，绝不混写），但**只摘取当前机位或遮罩区内实际可见的部位写入提示词**；画面拍不到的部位（如未戴的杯盖、未露出的底标、背面丝印、不存在的人物或道具）一律不写，也不为其堆砌负面词，既省上下文又防模型强行瞎画不可见部件。
- **纯无字底图与 PS 负空间预留**：进入电商项目出图写词时，优先读取根目录 `design.md`（白底结构锁与里程碑光影材质母体）和 `project.md` 对应行。只描写物理画面主体、证据动作、光影材质与给后期 PS 排版预留的低反差留白区；严禁要求生图模型画任何标题文案、价格角标、数字标尺、指示引线或放大圆框（仅按白底图保留产品本体原生刻字/丝印）。完成提示词后按编号就地覆盖写入 `制作/<编号_名称>/prompt.md`（未动工不预建）。
- 产品轮廓、比例、关键部件、材质和品牌区优先于风格描述。
- 做风格或光影追改时，先把“更暗、更通透、更电影”等抽象判断翻译成曝光关系、光比、阴影边缘和材质反射。阴天不等于整体欠曝：要写明均匀漫射光、收窄光比、提亮暗部、软化投影并保留暗部细节。
- 改色时优先保留主体材质的固有色，再写目标色彩如何进入暗部、中灰和高光；不要用“压低黄色、压低绿色、消除高光”这类单独的负向词把木材、植被或金属的真实颜色抽干。
- 材质必须写光打在表面上的结果。户外金属要承接天空的宽面积冷白漫反射，木材保留真实暖色与纤维层次，地面和主体要有统一的环境反射、接触阴影和边缘光，不能只堆“油润、真实、高级”。
- 写多图前复核目标图和参考图的实际状态，特别是原片、调色片和效果片混在一起时；目标图由本次要修改的素材决定，不由图号或画面明暗猜定。职责有冲突就指出并澄清，不能把已经调坏的效果片当成原始结构目标。
- 只写提示词时不调用接口；明确生图、改图或批量生成时，将最终任务交给 `d-image-runner`。
- 用户只要「对比原图审结构 / 一致性验收」时交给 `d-consistency-check`，本 skill 不代替三态审稿。
- 用户要「反推 / 拆参考图提示词」时交给 `d-prompt-reverse`（人判主次）；本 skill 不接一键终稿。

## 五维画面编译

每次写图片提示词都按以下顺序检查，不能只描述风格结果：

1. **职责解构**：先给每张输入绑定真实职责，分开结构、构图、光影、色调、材质和局部替换；主体轮廓、比例、关键部件与连接方式优先锁定。
2. **抽象转具象**：把“高级、通透、有质感、电影感”翻译成厚度、倒角、粗糙度、反射形态、接触阴影、边缘光和中灰过渡。
3. **光影按物理关系写**：明确光源位置与软硬，区分降曝光和改光比；需要阴天时写收窄光比、提亮暗部、软化投影和空间进深。
4. **色彩保护固有色**：用正向色彩倾向描述暗部、中灰和高光，保留木材、植被、食材等主体的固有色，不用粗暴去色制造暗调。
5. **动作闭环**：主指令明确写出保留什么、替换什么、移除什么、改善什么；只加画面中实际存在或用户明确要求的元素，不靠无关负面词填充。

## 改图提示词交付检查

图片编号与素材映射遵循 [图片引用格式](../../assets/image-reference-format.md)，统一使用 `@图1`、`@图2` 等。此规则也适用于高清修复、局部修复和方向探索，不限于普通改图；模型参数与文件名保持原样。

适用于 `edit / brief` 的最终图片提示词；用户仅问原因、讨论方向或要求差异说明时，不强套完整提示词格式。项目规则与用户明确指定的格式优先。

- 默认首行只写标准比例 `比例：1:1` 等；最终提示词放在可复制代码块内，块内首行重复同一比例。
- 多图按实际配套输入顺序用 `@图1 / @图2 / ...` 简述职责，角色说明放在代码块开头一次写清；单图省略角色行。主指令用一段描述画面，末尾一句集中收口关键约束。
- 默认提示词 250–450 字，复杂任务最多 600 字；不在每段重复结构保护与禁止项。代码块外需要说明变化时，只给 2–4 条短句。
- 追改先核对原目标、仍有效的参考职责和本轮变化。补充参考不自动替换旧参考；如精简输入，明确哪些图片不再传入、其仍有效的信息如何保留，不能静默漏图或重编号。
- 将“体积感、整体感、质感”等要求转成厚度、倒角、反射、粗糙度、光影等可见变化；不据此擅自重做未受影响的配色、排版或机位。只有确实阻碍执行的歧义才提问。
- 交付前单独检查代码块：离开聊天历史仍能知道改谁、改什么、每张图的用途；本轮未要求改变的决定保持有效。不得用“沿用之前”代替完整描述。

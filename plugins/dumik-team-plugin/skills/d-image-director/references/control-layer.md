# 控制层（全 mode 共用）

选定 mode 后、写 Prompt 前必读。本文件管「锁什么 / 放开什么 / 禁什么 / 优先级」，不替代各 mode 的 legacy 写词细则，也不替代 `prompt-contract.md` 的交付格式。

## 优先级 P0 / P1 / P2

| 级 | 含义 | 可交易吗 | 典型内容 |
| --- | --- | --- | --- |
| **P0** | 结构与身份 | **永不交易** | 比例轮廓、关键部件、接口按键、材质固有色家族、Logo/丝印占位 |
| **P1** | 品牌清晰与可读 | 仅用户明确降级时 | 卖点区清晰度、系列情绪/色结构、已确认设计语言 |
| **P2** | 氛围与装饰 | 可让步 | 次要道具、弱虚化、点缀色、非叙事必须的环境细节 |

冲突时：保 P0 → 再保 P1 → 最后才调 P2。禁止为「更好看的光」牺牲 P0。

## P0 结构锁清单

对照原产品图（或白底结构图）逐项确认；**不得重设计**。看不清的写「当前角度无法确认」，禁止猜测补全。

| 检查项 | 锁的内容 | 常见失败 |
| --- | --- | --- |
| 比例与轮廓 | 长宽比、外轮廓剪影、厚度感 | 拉长、压扁、圆角化 |
| 关键部件 | 把手、盖钮、刀刃、锅耳、支脚等可点名部件 | 增减部件、改形状 |
| 接口与按键 | 孔位数量/相对位置、旋钮、开关、插口 | 多孔、少孔、移位 |
| 材质固有色 | 不锈钢冷灰、钛金属倾向、木材暖色与纹理方向 | 整体去色、错成塑料感 |
| Logo / 丝印区 | 位置、大致占位；无清晰字时不编造可读文字 | 乱字、错标、漂到别处 |

写主指令时：先写「保留……」，再写「仅改……」。结构锁优先于风格词。

## 去抽象化（写进控制区）

抽象词必须译成**可检查**项，否则不算已控制：

| 抽象说法 | 必须补写 |
| --- | --- |
| 高级 / 有质感 | 厚度、倒角、粗糙度、反射形态 |
| 电影感 / 通透 | 主光方向、光比、阴影边缘、暗部是否有细节 |
| 大气 / 高级构图 | 主体位置、占比、俯仰、留白 |
| 保持产品不变 | 明确 P0 五项中的哪些 + 「不可改」 |

最少写清：**位置、镜头/机位、占比、光向、不可改项**。细则见 `prompt-segments.md`、`camera-language.md`、`lighting-control.md`。

## 控制区 vs 自由区

每条 Prompt（或 brief）至少在心里分清两区，复杂任务用一句话点明：

- **控制区（锁死）**：P0 全部；用户点名保留的关系；指定机位/构图（若已定）；P1 中已确认项。
- **自由区（可发挥）**：多为 P2；环境氛围、次要背景；未指定的弱光气质（仍服从系列规则与固有色）。

示例句式：`产品外形与按键布局以@图1为准锁定；桌面材质与窗外景深可按高级厨电氛围自由，但不得新增第二件主产品。`

未写自由区时，模型容易把「好看」理解成可改结构——宁可多写半句边界。

## 负面禁止项段落模式

约束集中写在 Prompt **末尾一句或短段**，只列**本任务真实风险**：

```text
禁止：乱码文字与水印；把手/接口变形或数量错误；凭空增加锅盖配件；改变 Logo 占位。
```

反模式：

- 粘贴超长通用 negative（blurry, low quality, nsfw…）却不写本图风险。
- 为画面里不存在的对象写负面（无人物却写 deformed hands）。
- 用负面去「抽干」固有色（消除所有高光 → 金属变死黑）。

## 系列规则表模板

成套主图 / 详情 / 车图共用时，先填下表再写单张；项目 `design.md`「设计语言」有内容则**强制继承**，无则标待确认。

| 维度 | 本系列固定 | 单张可调 |
| --- | --- | --- |
| 情绪 | （例：冷静专业 / 暖家常） | — |
| 光 | （例：侧上柔光、光比收窄） | 强度微调 |
| 色结构 | （例：中性灰台面 + 产品固有色） | 点缀色 |
| 镜头气质 | （例：微俯 3/4、中近景） | 裁切松紧 |
| 限制 | （例：无人物、无夸张特效字） | — |

单张「更好看」不得打破上表；要破例须用户明确同意并记入任务状态。

## 线稿分工

| 线稿类型 | 锁什么 | Prompt 该写什么 |
| --- | --- | --- |
| 产品线稿 | 外形、部件边界、接口关系 | 材质、光影、固有色、表面结果；**不要**再口述一遍已由线稿决定的轮廓 |
| 场景线稿 | 构图、主体占位、透视大关系 | 氛围、材质、光；**不要**与线稿抢机位或重排主体 |

同一控制点只由「线稿 **或** 文字」一方主责；两边都写满且互相打架时，以线稿结构 + 文字材质为准，并删掉文字里的重复结构描述。

## 设计语言

写词前若项目有 `design.md`：读取「设计语言」段（允许/禁止风格、清晰度优先级、系列规则）。与本文件冲突时：**P0 仍不可破**；P1/P2 以 design 已确认项为准。无 design 时不自造品牌调性。

## 反模式（禁止）

1. **抽象氛围词不落地**：只写「高级、通透、电影感、有质感」而不翻译成光比、反射、粗糙度、接触阴影。
2. **一键反推 Prompt**：未由人先判主次与控制区就当交付 → 交 `d-prompt-reverse` 协议，不在本 skill 偷跑终稿。
3. **通读全部 legacy 再开写**：未选 mode 或把 edit/hd/repair 规则揉进一条 Prompt。
4. **自由区吞掉控制区 / P2 压过 P0**：场景很美但产品已漂。
5. **系列漂移**：五张主图五套光色情绪，却声称同一套视觉。

## 与审稿的交接

结构是否漂移的**三态验收**由 `d-consistency-check` 负责。本文件指导写词前锁点；审稿发现问题后，回到本 skill 的 `repair` 或 `edit` 写修复指令，再交 `d-image-runner` 执行。

## 写 Prompt 前最小自检

- [ ] P0/P1/P2 冲突是否已按级取舍
- [ ] 结构锁五项是否都有「保留」或「无法确认」结论
- [ ] 抽象词是否已去抽象化（位置/机位/占比/光向/不可改）
- [ ] 控制区 / 自由区是否各有一句边界
- [ ] 负面段是否只含本图真实风险
- [ ] 成套任务是否已填或继承系列规则 / design 设计语言
- [ ] 有线稿时是否避免与文字重复争结构

全部勾完再进入分段/六段编译与最终代码块。

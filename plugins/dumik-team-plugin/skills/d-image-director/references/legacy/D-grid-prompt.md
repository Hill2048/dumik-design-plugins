# 四宫格抽卡提示词

四宫格是比较方向的一种形式，不是日常生图的必经阶段。本方法只在项目任务选用该形式时组织四格；已给定方向可直接写全幅提示词，不重做方向选择。

## 存在性优先

抽卡提示词只写视觉设定、参考图和当前创意方向中真实存在的主体、场景、道具与产品证据。不存在的对象不补写，也不为它们添加通用禁止项；风险收口只保留本次画面实际可能发生的产品结构、品牌区、构图或风格漂移。

输入来自当前项目已经明确的卖点、视觉证据和方向；可以由用户直接给出，也可以来自 `d-visual-plan`。本方法只展开当前需要的画面，不规定候选数或重新设计卖点。

## 执行边界

默认只输出可复制的中文提示词和批量行 JSON，不调用 `d-image-runner`、图片 API 或任何生图工具。

- 用户明确说生图、出图、抽卡生成、批量生成：把准备好的行交给 `d-image-runner`。
- 抽卡选片后产品细节偏了：交给 `d-image-director`。
- 确有策略缺项时交回项目总控，由其决定是否使用 `d-visual-plan`。

## 引用视觉设定，不重写身份

抽卡提示词不重新描述产品 SKU。读项目根目录 `design.md` 和相关 `设定集` 素材，用一句话引用产品身份；候选结果放当前图片任务目录，不建立公共抽卡目录。把 4 格之间的差异留给创意方向，把产品身份留给视觉设定。

这里的引用必须落实为本次实际传入的产品图片及必要文字，不能只给模型一个文件名或“遵循视觉设定”。四宫格之外的独立候选同样保持完整输入。

除 `设定集` 外，只使用用户本轮明确给出的文件。不得从 `素材`、`制作`、`成品`或外部素材库自动找图，也不得把上一轮候选自动作为新参考。

同时读视觉设定最前面的「视觉调性一句话」，把它当全套图的氛围底色（弱牵引），让调性一致，但不锁构图、不盖过产品身份。

## 按需使用 prompt-pack

`assets/detail-page-prompt-packs/` 提供可选表现方法，不覆盖用户给定方向，也不要求每个任务都匹配一个 family。

- 六个 family：对比证明 / 场景证明 / 材质微距 / 结构指示 / 生活方式 / 广告化。索引见该目录 `README.md`。
- 按卖点匹配 1-2 个 family（看 family 的 `suits_selling_points`）。
- 取 route 前先看该目录 `route-feedback.json` 的历史：同 family 下 keep 率高的 route 优先，连续翻车的降级。
- 选用四宫格时，可借用 family 的 `composition_variables` / `routes` 组织四格差异；不能为凑满模板擅自改写已定方向。
- 按 family 的 `common_drift` 做风险收口；按 `needs_white_bg_ref` 决定要不要带产品白底图参考。
- `fits_stage1_2x2=false` 的 family（如结构指示）不强塞 2x2，直接走全幅。
- 不匹配时按当前需求构思本任务，不自动新增或改写全局 family 资产。

## 段一：2x2 四宫格抽卡（低成本探方向）

用单张图内 2x2 四格，一次看 4 个创意方向。每格分辨率低，只用来探方向，不当详情页成品。

写法：

- 整图比例和分区分两层写。整图比例按详情页用途或目标图判断（默认竖版 9:16），内部排成 2x2 四宫格；四宫格只控制内部排版，不控制整图比例。
- 四格共享：同一个卖点要证明的判断、同一个视觉设定引用、同一个场景母版。
- 四格差异：只写视角、构图、场景、对比手法的差异，对应上游给的 3 到 4 个创意方向。不要在每格重复产品身份描述。
- 风险收口：只点最可能崩的 1 到 2 点（产品变形、品牌区错、四格风格不统一）。

段一只产出一条提示词（一张 2x2 图）。把它交给用户或 `d-image-runner` 出 1 张确认图，让用户挑哪个方向。

## 方向与任务溯源

展开既定方向时，记录其来源，防止多行候选混淆。方向是否已经确定由项目总控给出，本方法不另设确认闸口，也不要求已经给定的方向先生成四宫格。

记录位置按链路二选一，不要两边都写：

- **手动逐步链路**：写 `制作\图片\详情页-<卖点>\selection.json`（下方格式）。
- **autopilot 串跑**：方向决定由 `d-project-pipeline` 记进它的 run-state（`gates.direction` / `openGate`），本 skill 不另写 selection.json，只保证段二行带 `selected_direction_id`。

手动链路的 selection.json 格式：

```json
{
  "project": "纯钛+乌檀木菜板",
  "selling_point": "双面生熟分离",
  "stage": "direction_2x2",
  "selected_direction_id": "",
  "selected_image": "",
  "rejected": [
    { "direction_id": "", "reason": "" }
  ],
  "next_action": "expand_full_candidates | repair | final_composite | reroll",
  "notes": ""
}
```

使用方向 ID 时，让候选的 `id` / `output_name` 或运行记录能关联来源；用户直接给出的文字方向也可登记为任务方向，不要求用户理解或手填 ID。

## 段二：选中方向展开独立全幅候选（量产）

把当前已明确的方向展开为本次所需的独立全幅候选，数量与允许变化由任务输入决定。

规则按 `d-image-runner` 的多候选硬规则：

- 不要用 `count` 一行出多张。多候选必须拆成多行，每行 `count: 1`、不同 `id`、不同 `output_name`。
- 每行是一张独立全幅图，不是 2x2 小格，每张都能直接当详情页素材。
- 每行在选中方向内只微调一个变量：机位、距离、光线角度、对比强度、道具位置。产品身份仍引用视觉设定，不重写。
- 整图比例用选中方向的目标比例，不要先出别的比例再拉伸。

输出批量行形状（交给 `d-image-runner` 的 `提示词记录.json`）：

```json
{
  "items": [
    {
      "id": "卖点A-方向2-cand-1",
      "file": "产品白底图或目标图路径",
      "task": "卖点A 方向2 全幅候选1",
      "count": 1,
      "output_name": "卖点A-方向2-1.png",
      "output_size": "9:16-storyboard 或 2K，按比例依据",
      "final_instruction": "引用视觉设定的完整中文提示词，本候选只微调一个变量"
    }
  ]
}
```

## 方法选择

四宫格适合需要并排比较方向的任务，全幅适合已经明确方向或需要检查细节的任务。采用哪种形式、是否试跑和怎样选片由项目 `AGENTS.md` 与当前需求决定，不固定执行顺序。

## 输出

返回：

1. 视觉设定引用确认：用了哪份、产品身份一句话引用。
2. 段一：1 条 2x2 四宫格抽卡提示词（含整图比例 + 内部分区 + 四格差异）。
3. 需要全幅展开时，返回对应方向的独立候选 JSON。
4. 交接说明：要生图时怎么交给 `d-image-runner`。

## 交接

- 段一 2x2 和段二全幅候选都只写文字；实际生成交给 `d-image-runner`。
- 不调用图片接口、不优化已有改图指令（那是 `d-image-director` 的职责）。
- 不在四格或多行里偷偷改产品结构、把手、盖子、五金、品牌区、轮廓或 SKU 比例。

## 串跑溯源（Agent 模式）

在批量任务中，本方法提供已明确方向对应的溯源字段，复用任务现有记录，不规定确认或反馈范围。

- 段二每行除现有字段外，带上 `selected_direction_id` 和 `route_id`，对应 autopilot run-state 里 `task.directionId` / `task.routeId`，便于复盘「哪条 route 有效」。
- 输入更新后，只重新整理受影响任务的提示词，不自动回写项目设定或重编全部卖点。
- `selected_direction_id` 对应项目给定的有效方向，不能伪造用户已经确认。
- 手动逐步链路按原规则即可，本段只在 `d-project-pipeline` 串跑时生效。

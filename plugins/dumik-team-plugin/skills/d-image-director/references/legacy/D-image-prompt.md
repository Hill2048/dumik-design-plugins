# 图像提示词（改图 + 视觉 brief）

像美术指导一样写词，不当约束收集器。核心方法：**多图先点名每张图负责什么、单图直接说本次干嘛，再用一段话描述要改成什么，最后用一句短约束收口**。同一组保护规则只写一次，别反复写三遍。

## 存在性优先与最小充分描述

- 先看目标图和参考图中真实出现了什么，再决定写哪些主体、道具、动作、材质和约束。
- 最终提示词只写本次实际存在且需要保留、替换、修复或清除的内容；不存在的对象不补写，也不为了“完整”列出对应的禁止项。
- 负面约束只收口真实风险，例如目标图中确实存在的文字、Logo、结构漂移、穿模或材质错误；不要套用与画面无关的通用负面词。
- 参考图角色只说明该图实际提供的职责，不能把参考图里没有的主体或场景写进角色卡。

## 光影、色调与材质的改造逻辑

涉及阴天、电影感、暗调、去晴天光或整体质感升级时，先诊断画面坏在什么层，再写对应的可见变化：

- **氛围不是曝光**：静谧通透的阴天要写顶部或侧上方的均匀漫射天光、收窄整体光比、提亮原本死黑的暗部、软化投影边缘，并保留空气感和空间层次。只写“消除直射高光、压暗画面”会把晴天误处理成欠曝。
- **颜色不要靠抹除**：木材、植被、食材等主体固有色必须保留。把“深邃墨绿”“冷青灰”“温润暖褐”写成暗部、中灰和高光的正向色彩关系，避免用“压低黄色/绿色、转成冷灰”一类词把颜色抽干成脏灰。
- **材质要有环境依据**：金属需要承接天空或场景的宽面积漫反射、柔和高光和低对比环境形状；木材需要保留纤维、截面暖色和受控微光；地面、主体、阴影与边缘光要来自同一环境。主观形容词必须落到反射、粗糙度、光泽和接触关系上。
- **参考图要先验明身份**：多图同时出现原片、调色片和效果片时，按用户本次实际要改的素材确定目标图，再分别授权结构、构图、色调和材质。不要按图号、明暗或“看起来像目标”猜角色；若真实目标与提示词编号冲突，先澄清或明确按上传顺序暂定。

光影追改的主指令建议按“目标图与锁定内容 → 光源与光质 → 光比和暗部 → 固有色 → 材质的环境响应 → 空间融合”组织，最后只收口暗部死黑、颜色灰脏、反射断裂等真实风险。

## 五维画面思考框架

把一次改图拆成五个连续判断，先判断再写词：

1. **职责解构**：先确认每张图提供什么证据。目标图负责被修改的结构、构图和动作；风格图负责氛围、光线或色板；材质图只负责表面响应；局部图只负责指定部件。结构参考与风格参考不能互相越权。
2. **抽象转具象**：所有主观感受都改写成可见物理特征。体积写厚度和倒角；表面写粗糙度、反射带和高光形状；重量与融合写接触阴影、投影浓度、边缘光和台面反射。
3. **光影与氛围**：先确定真实光源、机位和空间进深，再确定亮暗关系。晴天转阴天的核心是减少直射、收窄光比、提亮暗部、软化投影边缘，不是把整张图压暗。
4. **色彩与层次**：先保护物体固有色，再组织暗部倾向和灰阶。用“暖褐木材、深邃墨绿、微冷青绿暗部、柔和中灰过渡”等正向描述建立层次，避免把颜色抹成灰黑。
5. **四动作加克制加法**：主指令必须能回答“保留什么、替换什么、移除什么、改善什么”；新增内容仅限真实存在或用户明确要求的对象。不要用堆叠负面词代替画面设计。

最终正文的优先级是：主体结构与身份 > 空间关系与动作 > 光影和色彩 > 材质细节 > 氛围修饰。风格改造不能反过来改变产品结构、动作关系或主体固有色。

## 执行边界

用户只说“写提示词 / 优化 / 改图指令 / prompt / brief”时，输出可复制的中文提示词或视觉 brief，不调用接口。

用户要求实际生成时，本 skill 准备完整 `final_instruction` 与实际参考清单，交给 `d-image-runner`。是否展示准备过程、何时推进以及怎样处理结果，由项目 `AGENTS.md` 与当前请求决定，本专业方法不另设确认或免审规则。

如果用户给的是已有视频、录屏，要拆关键帧、提口播、做图文报告，统一交给插件内的 `d-video-director`，不要改写成图片提示词。

## 生图快速路径

采用项目总控已明确可用的产品设定、参考和任务内容，不自行扩展来源。输入的职责决定其用法，不能仅凭图片数量判断哪张是目标图。

形成可执行输入时：

1. 根据本次意图区分修改现有画面与使用产品素材创作新画面，整理目标图及各参考的实际职责。
2. 使用本次有效画幅要求；编辑目标图时核对其画幅，新创作不因白底产品图比例而锁定画幅。
3. 将画面表达、参考采用的属性和需要保持的产品结构写进主指令，只保留相关风险约束。
4. 向执行器提供完整 `final_instruction` 和与正文编号一致的真实图片输入。

遇到无法支持画面的输入缺口或职责冲突，交回项目总控按其提问边界处理；不在本节另定用户确认方式。

## 模式选择

- **改图模式**（有明确目标图，对现有画面做修改）。其下再分：
  - 锁定：保留任务明确要求不变的结构、角度、构图、比例和 SKU；不把产品外观参考的机位误当成构图锁。
  - 人物锁定：换背景、棚拍白底或人像精修时，保人物身份、服装、身材、姿态和神态不变。
  - 创意：允许广告化重构、场景重建，但保产品可识别。
  - 多参考：多张图各管一件事（结构 / 场景 / 局部 / 材质）。
- **洗图模式**（套版/换皮）：给一张参考/灵感图，借它的构图、机位、光线、场景骨架，把产品和风格整体换成我的视觉设定。和改图相反——参考图是被覆盖的骨架，不是要保护的目标。详见下方「洗图模式」。
- **brief 模式**（无目标图或纯创意发散）：KV 概念、场景母体、氛围、材质光影方向。产出美术指导语言；如果最终要落成改图指令，再切回改图模式收尾。
- **线稿色块重绘模式**（模糊、脏污、结构和颜色都不稳定的图片）：先把同一张原图拆成黑白线稿、固有色色稿和一段真实的中文画面提示词，再用线稿与色稿约束重绘。该模式不是普通高频改图，也不是只做高斯模糊。

### 线稿色块重绘模式

当用户说“线稿色块”“按线稿和色稿修复”“把糊图重绘清楚”或提供了这类流程参考图时，按以下固定顺序组织提示词：

1. **线稿提示词**：只保留黑白两色，线条干净流畅，黑白层次清晰，去掉杂色、渐变、灰脏感和材质纹理；保持原图结构、比例、透视、轮廓和主体位置。
2. **色稿提示词**：只保留画面中各物体的固有色和色块关系，确保物体之间的固有色对比层次清晰；去掉多余杂色、渐变、阴影和纹理，不改变物体轮廓与位置。
3. **中文画面提示词**：从原图真实提炼主体、造型、材质、色调、光影来源、构图、镜头感和空间氛围，输出一段可以直接生图的成品提示词。不能把“请反推提示词”这类请求句当作成品。
4. **重绘提示词**：明确 `@图1` 为线稿、`@图2` 为色稿；依据 @图1 还原结构，依据 @图2 恢复固有色，再把第 3 步的成品中文画面提示词完整粘贴进来。最后集中写 3-6 个硬约束，保护产品身份、比例、透视、品牌区和关键部件。

该模式的技术交付包含线稿提示词、色稿提示词、中文画面提示词和最终重绘提示词。实际执行时交给 `d-image-runner`，展示与确认方式遵循项目总控，不另加步骤。

不要把改图任务改写成泛用文生图。

## 写词顺序

从项目已明确的任务内容取得目标、本次变化和产品识别点，组织成可执行的画面描述。

最终提示词按这个画面顺序写，保持紧凑：

1. 参考图角色（仅多图）：两张以上才用 `@图1 / @图2 / @图3...` 点名每张图作用；**只有一张图就跳过，别写角色行**。
2. 主指令：一段话写清本次要做什么——保留什么、替换什么、去掉什么、提升什么；不逐图重复解释。单图直接从这里开始。
3. 简短约束：最后一段集中写 3-6 个最关键的禁止项。

约束写法：约束只在最后集中出现一次，不要分散到每一段。先用正向可见描述，再用硬负面词；负面词必须对应目标图或参考图中可见、且本次确实要避免的风险。空话（更高级 / 更好看 / 更有质感）一律换成具体画面方向。

## 上下文与独立请求

有效的项目、系列与单图决定由项目 `AGENTS.md` 和当前任务记录提供，本 skill 不另定继承或失效规则。这里的职责是把这些内容写成一次独立完整的模型请求。

- 模型不能读取聊天历史或本地项目文件。需要采用的有效文字必须展开，所需图片必须实际传入并编号。
- 提示词中的 `@图1 / @图2 / @图3...` 与实际上传顺序对应，不用“上一张”“遵循 design.md”替代具体内容。
- 每份输入只采用其明确用途，不能将其他产品、场景或未获准使用的候选带进请求。
- 不因为加入一张补充参考就自行改写任务身份；只更新它实际影响的画面描述与素材编号。

## 追改 / 二次修改

将项目总控给定的本次变化并入对应画面描述，核对它是否影响透视、遮挡、光线或参考职责。

- 最终交给模型的仍是完整提示词，而不是需要模型自行拼接的历史补丁。
- 不改写未受变化影响的内容，避免修一个局部问题却重新设计其他部分。
- 如果用户要求“更有金属光泽 / 更清晰 / 更高级 / 更自然”，先翻译成可见光学行为，再并入主指令或简短约束，不要只堆形容词。

面向用户展示差异还是完整提示词，按当前请求与项目规则；技术交付保持完整，两者不冲突。

## 比例（第一行必写）

最终答复第一行必须只写 `比例：` + 比例池标准比例，例如 `比例：3:4`。第一行不要写依据、解释、约等于、图片尺寸或其他废话。真实图片尺寸只用于内部判断，不输出。最终代码块里的第一行也必须写同一个比例，例如 `比例：3:4`，因为用户复制代码块时模型也要吃到比例。

比例池：1:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9、21:9、1:4、4:1、1:8、8:1。

判断优先级：

1. 用户本次明确指定的比例，且该比例必须落在比例池；如果用户给了非比例池比例，要换算成最近的比例池比例，并说明依据。
2. 当前目标图（“这张图 / 目标图 / 修这张 / 沿用当前图构图”）控制整图比例；先看真实像素，再归一到最近的比例池比例。
3. 用户明确指定的画幅控制者（“以 @图4 为背景/场景/母版”）；先看真实像素，再归一到最近的比例池比例。
4. 被编辑图片的真实像素比例；先看真实像素，再归一到最近的比例池比例。
5. 场景母版参考图的比例；先看真实像素，再归一到最近的比例池比例。
6. 平台/用途比例（仅在没有任何图片控制者时）。
7. 默认用 1:1。

硬规则：

- 第一行禁止输出 `1565:2087`、`1024:1536` 这类像素比；只能输出比例池比例。
- 第一行禁止写“依据 @图1 / 约等于 / 原始画幅 / 目标图尺寸”等解释。需要判断依据时只在内部使用，不展示给用户。
- 代码块第一行必须重复同一个比例，且同样禁止写依据或解释。
- 真实目标图比例不明时，不许编数字。能查就查图片尺寸，不能查就第一行写“比例：需先确认目标图原始比例（不可猜）”。
- 不要因为是竖图或电商图就猜 4:5。
- 产品白底图、结构图、材质图、logo 图不控制整图比例，除非它本身就是被编辑的目标图。
- 宫格 / 故事板 / 2x2 抽卡：宫格只控制内部排版，不控制整图比例。两层分开写：先整图比例，再内部分区。

示例：外层第一行写 `比例：3:4`，代码块第一行也写 `比例：3:4`。

## 参考图角色

**只有一张图时不写角色行，直接说本次要干嘛。** 两张以上才需要点名分工。角色行只做“短角色卡”，不要把产品细节、文字位置、光影清单都塞进角色说明。

角色行硬规则：

- 每张图只写 1 句，尽量 20-35 字，最多不超过 45 字。
- 只写“这张图是什么 + 本次负责什么”，不要展开长清单。
- `@图1` 通常写成“目标图，锁定构图、产品结构、文字和主体位置。”
- 材质 / 光影 / 风格参考只写核心方向，例如“光影质感参考，控制明亮厨房柔光和清透金属高光。”
- “不控制比例 / 不改结构”只在参考图可能误导时短写一次，不要每张图都展开。
- 具体 SKU 细节、文字内容、部件保护、材质光学表现，统一写进主指令和约束里。

固定格式：

```text
图片角色判断：
- @图1：目标图，锁定构图、产品结构、文字和主体位置。
- @图2：光影质感参考，控制明亮厨房柔光和清透金属高光。
- @图3：材质参考，控制表面纹理和反射，不改变 @图1 结构。
```

硬规则：

- `@图1 / @图2 / @图3` 必须和用户上传顺序一致；看不清顺序时，先问或按聊天里出现顺序说明“按上传顺序暂定”。
- 角色判断要写“这张图是什么”，例如“@图1 是目标图”，“@图2 是钛面材质参考”，“@图3 是厨房光影参考”。
- 每张图只写核心职责，不要写成长段。特别是 @图1，不要把所有 SKU 细节逐项塞进角色行。
- 最终代码块里的提示词正文也必须引用这些编号，不允许只在代码块外解释。执行模型只看提示词时，也要知道每张图的作用。
- 角色说明只写一次，写在提示词开头；后文可以引用 `@图1 / @图2 / @图3`，但不要反复展开每张图的完整职责。

常见角色：

- 目标图：实际被修改的那张。用户含糊时，句子主语或“这张”就是目标图。
- 场景母版：控制背景、光线、相机、构图，通常也控制画幅。
- 产品结构参考：控制轮廓、比例、SKU、五金、部件、角度。
- 材质参考：控制表面、反射、纹理、颜色。
- 局部替换源：logo、徽标、把手、标签、部件。
- 风格参考：氛围、色板、光线性格、摄影语言。

## 产品身份锁

改图必须显式保护 SKU 识别点：轮廓与比例、盖子/顶部结构、把手与握柄、阀钮扣铰链等五金、品牌或 logo 区、材质工艺、配色和 SKU 专属细节，需要时含相机角度和产品姿态。氛围、光线、风格只能支撑产品，不能盖过它。不静默改动这些点。

## 电影化单帧增强

用户明确要求电影感、导演感、真人实景、品牌片静帧或高级商业摄影时，在原有 `锁定 / 创意 / 多参考 / brief` 模式上启用这一层，不另造新模式，也不改变中文紧凑输出形状。

内部先做五个决定，再编译成可见画面：

1. 摄影机站位：摄影机在主体的哪一侧、什么高度、离主体多远；观众为什么能从这里看到关键证据。
2. 唯一动作：只保留一个正在发生、尚未完全结束的动作或产品证据，不让主体只做摆拍。
3. 视线流量：视线从什么进入，被什么减速或遮挡，落到哪个产品结构、动作或结果，再由什么方向带走。
4. 物理光色：写清主色、辅助色、小面积强调色分别来自墙面、台面、窗、顶灯、工作灯、火焰或产品反射；不要用“电影滤镜”代替现实来源。
5. 成像基底：真实场地或实体搭景、可信材质、有限动态范围、柔和高光滚降、克制锐度和局部光学不完美；不要把颗粒、雾、光斑和青橙色当电影感。

比例改变时重新安排主体位置、留白方向和安全裁切区，不能只做机械裁切。产品身份、关键结构、品牌区和真实功能优先级高于构图风格。

电影、导演、海报或竞品参考默认只抽取一个主维度：构图方法、配色方法或题材方向。若用户明确指定多参考职责，则按角色卡分别授权；不得无意复制标志性人物组合、动作节点、道具组合、空间骨架和最终画面。

## 人物设定与身份锁

用户提到人物设定、模特、棚拍、纯白底、服装/身材/神态不变时，有目标人物图就默认走锁定改图。先锁“这个人是谁、怎么站、穿什么、是什么状态”，再改背景、灯光和摄影语言。

先判断输入职责：

- 目标人物图控制整图比例、裁切、人物身份、姿态、服装和表情。
- 用户给的参考提示词结构只提供写法、相机和灯光词，不得覆盖目标图里可见的人物特征。
- 场景或光线参考只控制指定层；人物图的身份锁优先级更高。

人物锁分六层，只写图中可见且和任务相关的证据：

1. 身份：年龄感、脸型、五官比例、个人特征和自然轻微不对称；不擅自换成泛化“网红脸”。
2. 妆发：发长、分缝、轮廓、妆面和配饰。
3. 身材：肩颈比例、躯干比例、体态、腰线和原有露肤程度。
4. 姿态：头颈角度、肩线、身体朝向、重心、手势、接触关系、原裁切和头顶空间。
5. 神态：视线方向、笑容开合、眼睑和面部肌肉状态；“神态不变”要改写成这些可见特征。
6. 服装：颜色、版型、领口、袖长、衣长、面料纹理、褶皱、闭合件、logo 和配饰；“服装不变”不能只写一句抽象保护。

提示词顺序固定为：本次改什么 -> 身份与神态锁 -> 身材/姿态/服装锁 -> 新场景 -> 相机与灯光 -> 皮肤响应 -> 短约束。用户给的英文或中文参考结构与人物保护冲突时，保护要求优先；例如参考结构写“25 岁、正面居中、肩部对称”，目标图不是这些状态时，不得照抄，改为“保持原年龄感、原姿态和原构图”。

纯白棚拍要写成可见画面：无缝纯白背景、无地平线、无灰角、无渐变，人物与背景靠受控轮廓光和干净边缘分离；原图有海报文字、logo 或环境残片且目标是干净棚拍时，明确清除。相机和镜头只塑造摄影质感，不得借机改变原裁切、身材、姿势和服装。

皮肤只做真实商业修图：半哑光、自然肤色、受控小高光、保留面部体积和目标图支持的细微纹理。不要为了“生物真实”硬加毛孔、红血丝、绒毛或油亮质感。

详细人物设定、人物锁定、纯白棚拍和多视角模特身份卡模板见 [references/templates.md](../templates.md) 的「人物 / 模特保真案例」。人物身份卡必须分成三视图板与面部特写板分别生成，再用脚本拼接；服装是本轮变量，不得把示例造型写成默认值。

## 引用视觉设定

项目里有 `design.md` 时，读取并提炼与本次画面有关的产品身份、场景和视觉调性，简洁写入最终正文；不能只写文件名或“遵循项目设定”。只有实际传入的产品白底/标准图才能编号（如 `@图2 = 设定集产品图`）。文字与图片共同保护必要的 SKU 识别点，避免重复罗列。调性当弱牵引统一氛围，不锁构图、不盖产品身份。

## 品牌文字

- 只有原图、用户请求或画面里已出现 DUMIK 类品牌文字时，才把 **DUMIK** 当标准拼写处理；文字残缺或拼错优先纠正为 DUMIK。
- 用户没提品牌、画面也没有品牌区时，不主动往提示词里加 DUMIK。
- 品牌纠正写成可见文字修正，不写成新装饰元素。

## 洗图模式

给一张别人的好图当版式，把里面的东西换成我的。典型输入：`@图1 = 参考/灵感图`，只借它的构图、机位、光比、场景骨架和氛围；我的产品来自视觉设定（`@图2 = 视觉设定产品图` + 文字身份）。只有参考图一张、产品靠文字/视觉设定描述时，按单图处理：不写角色行，直接说“做一张类似版式的图，换成……、去掉原图的……”。

- **物理脱壳与批量洗图工具（`scripts/wash_prep.py`）**：遇到带竞品本体、文字/水印，或参考图比例不对（如 `1:1` 需转详情页 `9:16` 顶部留白）时，先用 `wash_prep.py single` / `batch`（支持 `0~1` 百分比坐标）一键完成：① `--erase-box` 用洋红色块盖掉竞品轮廓防模型抄歪；② `--text-box` 吸周边背景色抹掉脏字与水印；③ `--target-ratio 9:16` 平滑延展顶部留白；④ 产出 `%TEMP%` 预览联系表与 DesignFlow 并发任务 JSON。

主指令一段写清：沿用 @图1 的构图、机位、光线和场景结构，把主体换成 @图2 的产品（身份按视觉设定锁住），场景和调性对齐我的视觉设定。末尾约束里必有一句：把 @图1 原来的产品、logo、文字、品牌元素换干净，只借版式不抄产品。

比例默认跟 @图1（留它的版式），除非用户另指定或视觉设定另有画幅。缺产品图或没视觉设定，就先要图或回 `d-visual-plan` 固化设定，别硬猜身份。

## 输出形状

本节给出文字提示词的专业交付范例。实际展示形式与确认安排以项目 `AGENTS.md` 和本次请求为准；生图时仍提供完整执行输入。

1. 第一行：只写比例，例如 `比例：3:4`（不可跳过，不写依据）。
2. 必要时用 2-4 条短句说明本轮修改；代码块外不另列图片角色说明。
3. 最终提示词放进代码块，方便整段复制；代码块第一行必须同样写比例，图片角色说明仅在这里出现一次：
   - 多图四段式：第一行 `比例：...`，第二段 `@图1 / @图2 / @图3...` 角色说明，第三段主指令一段写完，第四段简短约束。
   - 单图三段式：第一行 `比例：...`，第二段直接写主指令（本次要做什么、保留/去掉什么），第三段简短约束，不写角色行。

用户要“纯提示词”时，只输出包含提示词的代码块，不加块外说明；块内第一行仍为 `比例：...`。用户明确要求纯文本而非代码块时按其要求交付；多图保留角色说明，单图直接写主指令。

## 长度控制

- 多参考图改图提示词默认控制在 250-450 字，复杂产品最多 600 字。
- 图片角色判断默认控制在 1-3 行短句，总字数不超过整段提示词的 20%。
- 同一保护项只写一次；例如“保持 @图1 构图/角度/主体位置”写在角色说明或主指令里即可，不要在每段重复。
- 参考图职责、材质替换、清晰度提升、产品保护四类信息要合并表达，避免拆成五六个长段。
- 最后一段约束要短，优先保留真正会坏图的项：不改构图、不改产品结构、不新增物体、不脏污、不塑料感。

简洁示例：

```text
比例：3:4

@图1：目标图，锁定俯视构图、主体位置和厨房氛围。@图2：菜板材质参考，控制米白边框和雪花钛金属面。@图3：台面光感参考，控制暖灰金属台面和柔和反射。

以 @图1 为目标图做锁定改图：保持原 3:4 画幅、俯视机位、主体摆放、刀具和三文鱼位置；将菜板替换为 @图2 的米白厚实圆角边框与内嵌雪花钛金属面，透视贴合原菜板角度；将台面替换为 @图3 的暖灰银色金属台面，并提升整体清晰度、三文鱼新鲜感、菜板边缘、雪花钛纹理和台面反射的真实细节。

约束：不要改变 @图1 构图和食材数量，不要改变刀具形状和菜板把手结构，不要让雪花钛覆盖边框或食材，不要做成石材/水泥/塑料台面，不要过度锐化、脏污、噪点或塑料感。
```

## 最终提示词必须独立可用

- 图像与视频生成模型只能使用本次实际传入的素材和提示词，不能读取聊天历史、本地文件或项目记忆。助手可以承接用户已确定的设定，但必须将有效设定编译进最终正文。
- 禁止用“前面确定的女性”“沿用上一版场景”“按之前要求”“其他不变”等上下文指代替代画面描述。写清本次相关的人物外观、服装、场景材质、色调及修改范围；参考职责只说明一次，不为自洽堆叠无关细节。
- 每个素材编号必须对应本次实际输入或明确要求用户配套输入的素材，并在提示词正文中说明其职责。未传入的旧图不能伪装成已上传参考；可改成具体文字描述，确需身份图时在提示词外说明所需素材。
- 项目视觉设定、身份卡或上一版提示词可以作为助手的写作来源；最终正文必须展开必要内容，或引用实际传入且已编号的参考图。仅写文件名、路径或“遵循视觉设定”不能替代内容。
- 交付前只看最终代码块与配套素材检查：移除聊天历史后，仍能确定改谁、改什么、各参考负责什么、哪些内容保留。用户只要求差异句时可给差异；用户要完整版时必须整合，不让生成模型自行拼接历史版本。

## Guardrails

- 不写其他平台的提示词；不把改图任务改写成生成任务。
- 不静默改动「产品身份锁」里的任何一项。
- 保护性文字不许比修改方向本身还长。
- 不发明用户没要的功能和装饰。
- 不承诺参考图撑不住的连续性。

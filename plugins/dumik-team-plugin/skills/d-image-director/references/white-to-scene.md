# 白底转场景

目标：白底结构准 → 场景图仍像同一件产品。顺序固定，禁止先堆氛围再补结构。

## 强制步骤

1. **结构再锁定**  
   对照白底：轮廓、部件、接口、固有色、Logo 占位。写进 Prompt 前半「以 @图白底 锁定…」。

2. **接触关系**（最易崩）  
   产品如何接触台面/道具：放置、悬挂、嵌入、手持。写清支撑点、接触阴影、是否允许轻微遮挡卖点区。  
   示例：`锅底平稳坐在哑光石材台面；接触处有窄而软的接触阴影；锅耳不被道具遮挡。`

3. **功能态**（若有）  
   开盖/关盖、注水、火焰、食材 — 仅用户或策划要求时写；默认关态最稳。功能态不得改结构。

4. **场景层**  
   环境、景深、次要道具、窗光或灯带。明确自由区：`场景氛围可发挥，不得新增第二主产品或改锅耳。`

5. **机位对齐**  
   尽量接近白底常用的 3/4 或顶视约定；大改机位须用户同意，并预期结构验收变难。

## 禁止

- 用白底推断「统一视觉方向」（色温叙事、生活方式故事）——方向来自 design.md / 已确认场景参考。
- 先写「高级厨房氛围」再口头说一句「保持产品不变」（顺序反了）。
- 接触悬浮、穿模、无接触阴影的「贴图感」。

## 最小 Prompt 骨架

```text
比例：2:3
@图1：白底结构真源。@图2：场景光/氛围参考（可选）。

以 @图1 锁定产品外形、部件与固有色；产品[放置方式]于[台面]，接触阴影清晰。
场景：[一句环境]；自由区仅限环境与次要道具。
光影：与场景统一的[主光]，产品受同一光源；材质反射差保留。
禁止：结构变形；悬浮；乱字；第二主产品。
```

## 验收交接

出图后用 `d-consistency-check` 对白底做结构三态；不一致优先 `repair`/`edit`，不要靠再堆场景词掩盖。


## 常见崩坏对照

| 症状 | 多半缺了哪步 |
| --- | --- |
| 产品像另一款 | 步骤 1 结构再锁 |
| 漂浮/贴图 | 步骤 2 接触关系 |
| 开盖乱形 | 步骤 3 功能态未锁结构 |
| 场景漂亮但系列散 | 步骤 4 未继承 design |
| 广角锅耳弯 | 步骤 5 机位 |

## 与多视角

白底多角度已建资料库时（`multi-view-lock.md`），转场景优先复用同一角度家族，降低验收成本。

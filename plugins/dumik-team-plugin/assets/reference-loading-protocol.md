# DUMIK 参考文件读取硬门槛

本协议适用于所有 DUMIK skill。`SKILL.md` 里的参考文件链接不是目录提示，而是当前任务的执行规则。

## 必须执行

1. 先确定当前使用的 DUMIK 安装目录，再从当前安装目录读取本 skill、统一路由和参考文件。不得使用旧缓存、项目副本或记忆中的同名文件。
2. 建立本任务的 `reference_set`：当前 skill `references/` 目录下的全部文件都进入登记清单，再追加跨 skill、模式、模型和平台命中的条件文件。
3. 运行 `scripts/compile_reference_pack.ps1`。规则包必须包含全部参考文件的路径、大小、哈希和摘要；当前任务命中的文件进入正文区，未命中的文件只保留登记信息。
4. 在写策略、Prompt、任务行、提交参数或执行结果前，用真实文件工具逐个读取正文区中的命中文件。只读到文件名、链接、摘要或上次对话中的片段不算读取。
5. 读取后再开始判断和编译；不能边写边猜缺失规则，也不能用通用经验替代未读文件。
6. 在内部保留 `reference_receipt`，至少记录每个文件的路径、用途和读取状态。未读、读失败或版本来源不明时，不得声称遵循该文件。

命中文件里继续引用的本地规则、模板、示例或脚本也会自动加入正文区；外部链接不进入规则包。

## 读取范围

- 当前 skill 的全部参考文件：每次进入该 skill 都要登记并核对版本；当前任务命中的文件每次都要读正文，不因为上一次消息、摘要、压缩或“已经看过”而跳过。未命中的文件保留在索引中，不把历史正文无条件塞入当前上下文。
- 条件文件：当前任务命中对应模式、模型、平台、素材类型或输出形式时必须读。
- 旧版或历史文件：可以作为背景完整读取，但不能覆盖当前 `SKILL.md`、统一路由和当前模式规范。

## 缺文件处理

参考文件不存在、路径失效、内容无法读取或当前安装版本与链接不一致时，先报告缺口并停止依赖该规则的后续输出。可以继续做不依赖该文件的路由判断，但不能默默降级、套旧版本或直接执行。

## 完成条件

只有同时满足下面三点，才算参考文件读取完成：

- `reference_set` 已确定；
- 当前 skill `references/` 下全部文件、所有命中的条件文件已登记并核对；所有命中的文件已真实读取正文；
- 最终输出逐项通过这些文件定义的格式、边界和检查项。

用户不要求展示内部回执时，不把回执全文塞进最终 Prompt；需要说明时只简短列出实际使用的参考文件。

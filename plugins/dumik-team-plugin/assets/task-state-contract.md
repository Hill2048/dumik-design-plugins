# DUMIK 任务状态合同

本合同与项目根目录 `project.md` 分工明确：
- **项目级总进度**：统一由根目录 `project.md` 表格维护（通过真实文件校准状态，不建 `.json` 队列）。
- **单图/单镜当前生效工作状态**：按需落在具体任务目录下，就地覆盖更新，不留 `v1 / v2` 历史废稿或运行日志。

## 一、图片任务单图档位置

```text
制作/<编号_名称>/prompt.md
```

- **未动工不建目录**：未开始写词或标记为 `无需生图（后期排版）` 的分屏，绝不提前创建空目录。
- **参考图物理隔离**：`素材/飞书画布/` 中的参考截图仅供写词前视觉阅读理解构图、对比张力与压字明暗，严禁写入 `prompt.md` 的 `@图N` 绑定；`@图1` 仅收自有白底图，`@图2` 仅收自有里程碑定稿图。
- **定稿晋升**：候选图经用户确认后，交 `build_canvas_pipeline.py --promote <编号> --file <候选图>` 复制入 `设定集/里程碑/`（`MS*`）或 `成品/` 对应画幅目录（`S*`/`M*`/`E*`），并自动刷新 `project.md` 状态与 `当前出图` 缩略图。
- 视频任务沿用 `制作/视频/<任务名>/任务状态.md` 兼容单镜多轮返修。

## 三、覆盖更新与恢复规则

1. **每次追改直接覆盖 `prompt.md`**：先读 `prompt.md` 与 `design.md`，把用户本轮变化直接合入唯一正文并写回原文件；旧词不保留在同目录下，防止后续 Agent 搜索时新旧混读串味。被明确否掉的写法记入顶部「明确不采用」一行提醒自己不走回头路。
2. **完整独立正文**：传给生图模型的正文必须独立自洽，严禁出现「在上一版基础上」「其他不变」等依赖聊天历史的省略语；所有文本描述保持干净纯画面，严禁要求生图模型渲染后期文案或标尺。
3. **非授权不重抽**：写完或更新 `prompt.md` 只代表状态变为 `提示词就绪`，绝不自动触发 `d-image-runner` 生图；必须等用户明确下令才按批次或编号提交，且批次完成后立刻销毁 `%TEMP%` 临时队列。
4. **单次不建项目场景**：用户明确要求零散单图改词、不建项目目录时，直接返回完整代码块，不强建目录或状态文件。

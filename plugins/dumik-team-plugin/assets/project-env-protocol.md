# 项目入口与环境协议

本文件提供项目结构、来源边界和环境检查的通用默认规则，不承担每个项目的日常调度。项目自己的 `AGENTS.md` 记录实际采用的协作方式和流程；通用规则更新不自动覆盖项目定制。

## 项目入口协议

用户指定的项目文件夹就是项目根，其中的 AGENTS.md 优先。新项目采用下述设定集结构；已有项目遵循其明确规则，不自动迁移或删除旧资料。

项目根的两个入口文件为 AGENTS.md（项目总控、协作与工具）和 design.md（视觉设定、来源和确认状态）；目录与使用说明并入 AGENTS.md；不另建 `agent.md`，不建项目指针或历史文件（`CURRENT_PROJECT.md`、`CONTEXT.md`、`CLAUDE.md` 已废弃）。项目身份由文件夹本身确定，不靠指针记录。用户确认基础设定和确认成品是两个不同决定。

## 总控归属

- `d-init` 是入口文件生成与维护工具，不是每个任务都要经过的调度 skill。初始化时根据项目类型、已有文件和用户已确认的工作方式生成 `AGENTS.md`；用户要求维护时只改相关规则，保留项目差异。
- 日常任务由项目 `AGENTS.md` 统筹理解需求、继承已确认内容、参考使用、专业方法调用、确认时机和结果处理。项目未定义的部分才采用插件默认方法；skills 内的固定阶段、默认提问或展示方式不覆盖项目的明确安排。
- 专业 skills 负责其领域的方法与接口用法，不各自建立另一套项目决定或重新确认用户已经确定的内容。项目可调整协作方式，但不豁免真实素材、技术兼容性、凭据保护和执行授权要求。
- 协作规则放 `AGENTS.md`；产品、场景、角色及其确认状态放 `design.md` 与 `设定集`；单图、系列和单次执行记录跟随制作任务。不为这些层次另建调度技能或强制用户填写多份表格。
- 多轮追改按 [任务状态合同](task-state-contract.md) 复用当前明确任务的说明或运行记录；纯文字任务不因这一规则强行建项目，恢复不靠扫描其他任务。
- 用户明确点名当前图作修改，或已经授权某文件在本任务、系列内继续使用，即有相应范围的输入用途，不重复索要相同许可；不据此扩大到其他任务或项目设定。
- 维护已有项目时，`d-init` 不重新初始化目录或检查生成接口，除非维护内容确实需要。插件更新也不扫描并重写各项目 `AGENTS.md`。

## 参考来源硬规则

- 默认只使用项目 `design.md` 和 `设定集` 中与当前任务相关的内容。
- 白底图只能用于确认产品外观、结构、颜色、丝印和配件关系；不得据此填写或推断场景、台面、背景道具、整体风格、光线、色温、构图、机位、文案排版等“统一视觉方向”。统一视觉方向须来自用户明确确认的文字设定、`设定集/场景`、`设定集/角色`、KV 或其他方向性素材。
- `素材`、`制作`、`成品`和外部素材库只负责存放或归档，不代表授权作为参考；不得自动扫描、挑选、回垫或从历史产物中推断参考。
- 用户本轮明确上传、给出路径、点名文件或明确说“使用我刚放入素材的文件”时，该文件可用于本次任务；必须记录它的角色，不自动升格为项目设定。
- 设定集为空且用户未提供参考时，纯文字任务照常执行；生成必须依赖视觉或音视频输入时，只问缺少的具体文件。

项目制不是默认强制开启，先看用户意图和用户指定的项目文件夹。

- 用户指定了项目文件夹，且要项目制、批量、多轮沉淀、确认图/片后批量：以该文件夹为项目根，直接读其中的 `AGENTS.md` 和 `design.md` 开工，不重复问项目名。
- 用户没指定项目文件夹，且要项目制、批量、多轮沉淀：先问项目文件夹路径，以及图片项目 / 视频项目 / 混合项目。
- 用户明确说切换项目：以新指定的项目文件夹为准直接切换，不维护任何指针文件。
- 用户明确说不进入项目：本次按单次任务处理，产物不强制归任何项目。
- 用户只要一句提示词、一次改图、一次单图/单条生成，且没有项目制表达：按单次任务处理，不要为了“完整”强行建项目。

## 项目目录

项目根就是用户指定的项目文件夹，不嵌套 `project\<项目名>`。项目目录以设定集为核心。图片和视频共用同一个项目根目录，不再创建旧的 `原图`、`参考`、`输出` 结构：

```text
<项目文件夹>\
  素材\
  设定集\
    白底图\
    场景\
    角色\
  制作\
    图片\<任务名>\
    视频\<任务名>\
  成品\
    图片\
    视频\
  AGENTS.md
  design.md
```

输入和候选可以存进 `素材` 或 `制作`，但存放不等于允许作为参考。制作内全部是未确认结果；用户确认 OK 后才进入成品。抽卡、提示词、运行记录和临时文件跟随具体任务。

## 归档规则

- 尚未整理的原始产品资料、参考图、参考视频和音频放 `素材`。
- 已确认并可长期复用的产品外观、场景和角色放 `设定集` 对应子目录，并在项目 `design.md` 登记来源和状态。
- 图片任务落 `制作\图片\<任务名>`，视频任务落 `制作\视频\<任务名>`；提示词、候选、确认前结果、运行记录和临时文件跟随任务。
- 用户确认 OK 的正式图片放 `成品\图片`，正式视频放 `成品\视频`。
- Eagle、本地素材库、飞书画板等外部素材默认不读取、不引用；用户明确点名后才可只读使用。除非用户明确要求，不复制、不移动、不写回原素材。

## 环境部署时机

纯入口文档生成或维护、规则解释、只写提示词或方案，不因项目制、多类素材或读取设定集而触发环境部署；不为这些任务补制作目录、初始化 API 缓存、安装生成依赖或探测生成接口。用户明确要求完整工作台初始化时，按其范围处理。

实际执行确实需要项目环境时，再按以下情形检查和补齐所需部分，不重建已有环境：

- 用户明确说项目制、批量、多张、整组、成套、先出确认图/片、确认后批量、提交 Dreamina / Veo。
- 实际生图/生视频且后续会继续沉淀素材或多轮返修。
- 任务包含多类素材：素材、设定、提示词、未确认结果、成品和运行记录。

## 检查清单复用

全量环境检查不要每次重复做。先读 `assets\verified-environment-checklist.md`：

- 清单版本与当前插件版本匹配时，复用清单结论，不重复检查插件结构、脚本存在性、Python、FFmpeg、Dreamina 和敏感信息扫描。
- 只做本次项目级检查：项目目录、设定集、任务目录、输入文件、提示词 JSON 和输出路径。
- 实际调用接口前，再轻量确认动态项：API 缓存、本次权限、Dreamina 登录 / Veo 权限、FFmpeg（需裁切转码时）、Banana2 本地参考图的 tunnel URL 可达性。

## 工具检查

进入实际生成、批量、项目制前检查：

- Python 可运行；对应执行 skill 的 `init_project.py` / `generate_batch_images.py` / `generate_batch_videos.py` 存在。
- 接口配置可读：优先本机 `CODEX_HOME\dumik-team-plugin\api_settings.py`；没有时运行插件根 `scripts\init_api_cache.py` 初始化；仍没有再读 `CODEX_HOME\config.toml`、`CODEX_HOME\auth.json` 和环境变量。
- Dreamina 路线：`dreamina` CLI 可用，提交前先看对应子命令 help。
- 视频拆解报告：`ffmpeg`、`ffprobe` 可用；需要生成本地关键帧下载数据时再检查 `node`。
- 需要本地参考图公网 URL 时：NAS 发布配置或临时 tunnel 脚本可用。

## 自动修复边界

能自动修复的直接做，不烦用户：

- 缺项目目录或四大主目录：创建补齐；不要创建旧的 `原图`、`参考`、`输出` 分类。
- 缺 API 缓存但本机配置存在：运行 `scripts\init_api_cache.py`。
- 缺 Python 依赖且有明确依赖文件或脚本报缺模块：当前环境安装后重验。
- 缺 FFmpeg 且本机包管理器可用：自动安装后重验。
- `d-video-director` 需要下载数据脚本且缺 Node.js：优先安装 Winget 包 `OpenJS.NodeJS.LTS`，再复查 `node --version`。

不能自动处理才停下说明缺口：

- 缺 API key / token；Dreamina 未登录、额度不足或需网页确认；Veo / NewAPI 缺权限。
- 没有可用公网参考图发布路径，且 Banana2 必须读本地参考图。
- 安装需要登录、管理员权限或外部账号确认。
- 视频参考超平台限制，且自动裁切会改掉用户想保留的关键内容。

## 最小提问规则

只问会卡住下一步的问题：缺项目根问项目文件夹路径和项目类型；改图缺目标图问哪张；生成缺模型或完整提示词问缺项；视频缺时长/比例/主卖点且影响镜头结构时只问缺的关键项。其余能从当前项目、素材记录或语境判断的，不重复问。

# 项目入口与环境协议

本文件规定 DUMIK 项目文件夹的标准形态、参考来源边界与环境检查规则。**一个产品一个独立项目文件夹，文件夹本身即完整上下文**，无需跨项目指针文件（`CURRENT_PROJECT.md`、`CONTEXT.md`、`CLAUDE.md` 已全部废弃）。

## 一、根目录精简结构（四文档 + 四目录 + 零过程垃圾）

```text
<项目文件夹>/
├── AGENTS.md                 # 【项目工作规约】极简铁律 + 仅 @内联挂载 design.md（防超 24KB）
├── design.md                 # 【纯视觉宪法】只写审美定调、产品工艺锁、材质光学公式、光影母体与硬禁令
├── assets.md                 # 【资产与置景台账】按需读取：锁定资产路径/哈希、8~12件风格摆件库、饮品/食材排期、Eagle ID
├── project.md                # 【唯一项目总账本】按需读取：产品事实、飞书源、第0~3批画面清单、物理证据与状态
│
├── 素材/
│   ├── 实拍原图/             # 原始实拍图、包装图（初始化自动归整根目录散放图片）
│   └── 飞书画布/             # 仅存放拆解下载的有效画布参考图（竞品参考不落地）
├── 设定集/                   # 【唯一合法参考源】已锁定的白底基准、里程碑与摆件/人物/场景身份卡
│   ├── 白底图/
│   ├── 里程碑/
│   ├── 摆件身份卡/
│   └── 必渲特写/
├── 制作/                     # 按需建子目录，不预建空文件夹；仅在动工时建立 <编号_名称>/
│   └── <编号_名称>/
│       ├── prompt.md         # 仅保留当前最新生效的一版完整提示词与 @图N 绑定（覆盖更新）
│       └── 候选_01.png
└── 成品/                     # 用户验收确认的终稿交付物
    ├── 详情_790xn/
    ├── 主图_3x4/
    ├── 入口与SKU_1x1/
    └── 审稿报告/             # d-detail-review 终稿排版审查输出（离线悬浮 HTML 审稿台 + 红框标注大图，零 .json）
```

## 二、零本地运行垃圾硬规矩

1. **禁止往项目内写入任何 `.json`、`.log` 或历史流水账**：
   - 不在项目内落地 `canvas-manifest.json`、`拆解清单.md`、`run-state.json`、`wave*.json`、`results-input.json` 或 `.project/` 隐藏目录。
   - 不在 `制作/` 或任何图片输出目录默认写出 `运行记录.json` 与 `运行记录.md`（仅基准测试或显式 `--write-run-record` 排错时使用）。
   - 批量生图所需的临时批次 JSON 一律生成在系统 `%TEMP%\dumik-runs\`，调用结束后立即删除；技能参考拼装包继续只输出在 `%TEMP%\dumik-reference-packs\`。
2. **真实文件即真相**：某屏是否已就绪、有几张候选、是否已定稿，以 `制作/<ID>_*/prompt.md`、`制作/<ID>_*/候选_*.png`、`设定集/里程碑/` 与 `成品/` 下的实际文件为准（可运行 `d-project-pipeline` 的 `--status` 自动校准回 `project.md`）。

## 三、总控归属与项目判定

- `d-init` 是一键建档与飞书增量同步工具（`scripts/init_dumik_project.py`），初始化完成后日常工作直接依据根目录 `AGENTS.md`、`design.md`、`assets.md` 与 `project.md` 推进。
- **用户指定了项目文件夹，或打开一个新建产品目录**：使用 `d-init` 建立上述四文档 + 四目录结构；已有项目保留用户定制，只在 `--sync` 时增量合并 `project.md` 并保留已锁定/已定稿进展。
- **单次纯文字/单图临时请求**（用户明确不建项目）：按单次任务直接响应，不强建整套目录。
- `d-image-runner/scripts/init_project.py` 与 `d-video-runner/scripts/init_project.py` 必须对齐本协议目录，严禁再嵌套 `project/<名称-时间戳>`。

## 四、参考来源与纯无字画面硬规则

- 默认只从项目 `design.md`、`设定集/` 及当前 `制作/<编号_名称>/prompt.md` 中已登记的参考图取用；不得自动扫描 `素材/` 或外部图库当参考。
- **白底图职责严格限定**：白底图只用来锁定外观比例、关键部件数量与颜色家族，**严禁依据白底图棚拍光线、白背景或机位去推断全局场景调性**；统一风格必须来自里程碑定调并写入 `design.md`。
- **纯无字画面原则**：AI 只负责生成带干净低反差留白的纯画面底图，后期标题、卖点文案、数字标尺、指示引线与角标由用户人工在 PS 中排版。

## 五、环境检查与最小提问

- 纯入口创建、规则维护、飞书拆解列清单、只写 `prompt.md`，均**不触发**接口探测或图片生成依赖检查。
- 实际调用生图或视频接口前，检查 Python、关键脚本与本机 API 缓存（优先 `CODEX_HOME\dumik-team-plugin\api_settings.py`，缺失时跑 `scripts\init_api_cache.py`）。
- 只问会阻塞下一步的关键缺口（如：缺产品白底图、缺飞书链接且未给卖点、模型或批改授权未下达）；已确定进 `project.md` 或 `design.md` 的内容绝不重复确认。

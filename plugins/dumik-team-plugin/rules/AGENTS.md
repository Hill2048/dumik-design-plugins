## 二、全案不可破底线

1. **纯无字底图 + 三层参考隔离 + 光学材质底线**：除产品本体原生丝印/刻字或用户明确指定画内结构字（标 `[画内字白名单]`）外，严禁标题、卖点字、标尺、引线、圆框；带水印/UI 的 `素材/飞书画布/` 截图仅作写词前看图用，**严禁喂入 API**；说「不要垫图」只清历史废稿与临时参考，**绝不误删白底图、人物卡与已定稿概念母版**，发包前去重；实景生活屏优先直垫干净真机实拍图，**凡出现任何人物（含仅露手/腕/袖/肩背特写）必须无例外垫入人物身份卡**；透明容器/实验缸/护盾严禁普通玻璃青绿切边（统一写无铁纯无色光学石英水晶），双仓防锈/抗腐对比介质须左清右浊、拼色底座无缝咬合且水中器物坐实缸底；塑胶/烤漆等部件须按实物真实光泽度写词（忌直写「PP/塑料」出灰暗廉价感，哑光实物禁乱加「骨瓷/高光」防过冲油光）。
2. **零本地运行垃圾 + 全流程中文命名**：项目内禁止落盘 `.json` 队列、`拆解清单.md`、`.pytest_cache` 或 `运行记录`；**全流程所有候选图、导出图、修复图、联系表与文件夹名称必须使用中文**（仅保留标准编号 `MS/S/M/E` 与扩展名，如 `候选_01.png`、`<原名>_已修复.png`、`<原名>_已修复.psd`，严禁 `s01_float_1.png`、`candidate`、`_repaired` 等英文命名或英文后缀）；生图结束立刻 `--status` 同步 `project.md` 并清理 `%TEMP%\dumik-runs\`。
3. **授权与汇报**：未收到用户本轮明确下令「开始生图 / 出图 / 生成 / 跑图」前绝不调付费接口；列举任何编号必须写成 **`编号 4~6字卖点`**（如 `S01 健康对比`），极简中文人话，不自建 PR/分支。

## 三、插件发版与公告规则

- **仅在用户明确下令时才推送与发版**：日常修改插件代码、Skill 或脚本后只在本地保存并完成测试，**严禁私自 `git push` 或发行 GitHub Release**；只有用户本轮明确说「推送 / 发布 / 发版」时，才递增版本号（默认 `+0.0.1`）同步更新 `.codex-plugin/plugin.json`、`plugin.json`、`assets/skill-versions.json`，并运行 `scripts/release_dumik_plugin.ps1 -NotesFile "<公告>"` 发新 GitHub Release。
- 公告必须基于 `git log <上个tag>..HEAD` 汇总**全部**实际变化，**禁止写 `# DUMIK Team Plugin v...` 重复一级标题**，按 `✨ 新功能 / ⚡ 优化与改进 / 🐛 问题修复` 列 `- **加粗人话小标题**：一两句讲清变化`，末尾附 `compare/<上个tag>...v<新版本>` 链接。
